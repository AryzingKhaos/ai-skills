# B 站视频转文字稿

把一个 B 站视频链接，变成一份**读起来顺、分好段、每段有小标题**的简体中文文字稿。

整条链路：**下载音轨 → whisper 转写 → 整理成文稿**。前两步是确定性的，用 `scripts/`
里的脚本跑；第三步「整理」是真正需要你动脑、也是用户最看重的部分，规则见下文。

---

## 0. 前置工具

需要 `yt-dlp`、`ffmpeg`、`openai-whisper`(python 包)。开工前快速自检，缺了就装：

```bash
command -v yt-dlp ffmpeg >/dev/null && python3 -c "import whisper" 2>/dev/null \
  && echo "OK" || echo "缺工具"
```

- 装：`brew install yt-dlp ffmpeg` ；`pip install -U openai-whisper`
- `whisper` 命令行常不在 PATH，没关系——转写走 `scripts/transcribe.py`（用 python 包）。

**网络相关命令（yt-dlp 下载、whisper 首次下模型）在沙箱里会被拦，必须
`dangerouslyDisableSandbox: true` 运行。**

---

## 1. 开工前先和用户确认（很快）

至少确认这两点，其余用默认值即可：

- **主要语言**：默认中文（`zh`）。B 站视频先看标题猜，多数是中文。
- **输出位置**：默认 `~/workspace/aiDownload/<视频短名>/`，可让用户改。

可顺带问（有默认值，不强求）：

| 项 | 默认 | 备注 |
|---|---|---|
| whisper 模型 | `medium` | 见下方「模型档位」 |
| 交付物 | 整理好的 `.txt` 文稿 | 如要原始转写/字幕另说 |

**模型档位**（CPU 转写，时长按音频长度估）：

- `small`：最快，但专有名词/数字易错，需更多人工校对。
- `medium`：**默认推荐**，中文已相当准，速度/质量平衡。
- `large-v3`：最准（中文明显更好），但慢很多。时长可观时**放后台跑**、跑完通知用户。

---

## 2. 下载音轨

```bash
bash scripts/download_bili_audio.sh "<视频URL>" "<输出目录>"
# 需要 dangerouslyDisableSandbox: true（联网）
```

脚本会：自动依次试 chrome/safari/edge/firefox 的登录 cookie 过 412 反爬 → 下载音轨 →
抽成 16kHz 单声道 wav。成功后打印 `TITLE=` / `DURATION_SEC=` / `AUDIO=`，用 TITLE 给
输出目录/文件命名，用 DURATION 估转写耗时。

**关于 412**：B 站对无会话请求返回 `HTTP 412 Precondition Failed`，加 UA/Referer 甚至
buvid3 都不够，**必须带浏览器里的 B 站登录 cookie**。脚本默认遍历常见浏览器；若全失败，
说明用户没在任何浏览器登录过 B 站，或需要用第 3 个参数指定浏览器（如 `... chrome`）。

---

## 3. 转写（长任务 → 放后台）

```bash
python3 scripts/transcribe.py "<输出目录>/audio.wav" "<输出目录>" medium zh
# 放后台执行（run_in_background: true）+ dangerouslyDisableSandbox: true（首次下模型联网）
```

CPU 上 medium 转十几分钟音频可能要十几到几十分钟，**会超过单条命令超时，所以必须放后台**，
完成后系统会通知你再继续。产物：`raw_transcript.txt`（整段原文）、`segments.txt`（带时间轴）。

转完先确认简繁：whisper 中文偶尔吐繁体。`grep` 几个繁体特征字（這個來時學說對國錢產萬）
若命中较多，整理时统一转简体（第 4 步本来就会重写为简体，所以问题不大）。

---

## 4. 整理成文稿 ★（核心，用户最看重）

这一步**你亲自做**，不要交给脚本。读 `raw_transcript.txt`（必要时对照 `segments.txt`
看话题切换点），把一大坨流水账重写成可读文稿。目标是**好读**，同时**忠实原意**。

### 4.1 结构：三级 + 「每段一个小标题」

原始转写最大的毛病就是「一整块、没有段」。所以**宁可切细**：

```
大节（按话题/作者列举的要点切，如「误区一/误区二…」）
  小段（一个小话题，2–5 句话）
    ▸ 小标题（4–12 字，概括这一小段）
```

排版用纯文本可读的分隔即可，例如：

```
════════════════════════════════
二、误区一：没钱，就没必要学投资？
════════════════════════════════

▸ 最常被问：没钱，学投资有意义吗？
（这一小段的正文，2–5 句）

▸ 学投资 ≠ 小本金翻身
（正文）
```

**关键：几乎每个小段都要有 `▸` 小标题**——这是用户反复强调的点。段落别太长，长了就再拆。

### 4.2 清理：可改什么、不可改什么

- **补标点、分句**：口语没有标点，按语义加。
- **轻度去口水**：删「然后然后」「就是就是」「这个这个」这类重复语气词、明显的车轱辘话；
  但**不要删观点、例子、数字**。
- **修明显口误（ASR 同音错字）**：只在**上下文能确定本字**时改，且是发音相近的误识，
  例如（来自实战）：上星→上心、回车→回撤、主持人的开启→主升浪的开启、产销电力→长江电力、
  临时起义→临时起意、满车杠杠→满仓杠杆、短信大佬→短线大佬、无头苍蝇、二一→2021。
- **统一简体**：若有繁体，转简体。

**红线——这是转写不是创作**：不臆造原文没有的事实、数字、观点、背景；拿不准的词宁可保留
原样，别「猜着补全」。遇到大段含糊/重复到无法还原的口胡，按可辨识的意思**精简成一句**，
不要凭空展开。

### 4.3 文稿抬头

正文前加一小块元信息，便于溯源：

```
《<视频标题>》文字稿

来源：<视频URL>
说话人：<能判断就写> ｜ 时长：<mm 分 ss 秒>
转写：whisper <模型>（<语言>）。本稿已整理——细分小段、每段加小标题、补标点、
修正明显口误，内容忠实原意，未增删观点。
```

最终文稿存为 `<视频短名>-文稿.txt`。

---

## 5. 收尾

- 删大文件 `audio.wav` 和中间的 `segments.txt`；保留 `raw_transcript.txt`（原始备份）
  和最终 `*-文稿.txt`。
- 给用户报：文件路径、小标题骨架、可选下一步（压成一页要点速记 / 按其知识库流程 ingest）。

---

## 常见坑速查

- **HTTP 412**：B 站反爬，必须 `--cookies-from-browser`（脚本已自动遍历浏览器）。
- **`whisper` 命令找不到**：用 `scripts/transcribe.py`（python 包），别找 CLI。
- **转写超时**：放后台（`run_in_background`），别前台干等。
- **沙箱拦网络**：下载/下模型的命令加 `dangerouslyDisableSandbox: true`。
- **吐繁体**：第 4 步重写为简体即可，不用单独装 opencc。
- **多分 P 视频**：yt-dlp 默认取当前 P；如需整册另议。
