# Roleflowv2 角色加载器

按用户指定的角色名加载对应的角色定义文件，**并同时解析本次的任务ID 与工件落盘目录**，把三者作为后续协作的最高优先级行为约束。另支持 `switch` 子命令在已有任务之间切换（保留当前角色）。

## 调用语法

主命令：

```
/roleflowv2 <角色名> [<任务名称（中文/camelCase/完整任务ID），可能带有版本号>]
```

切换子命令：

```
/roleflowv2 switch <任务名（中文 / camelCase / 任务ID 子串）>
```

初始化子命令：

```
/roleflowv2 init
```

> 子命令 `switch`、`init` 的**完整流程按需加载**：仅当用户实际调用时，才读取并严格执行 skill 目录下对应文档（`switch.md` / `init.md`）；不调用就不读，避免占用上下文。详见 §子命令（按需加载）。

- `<角色名>` 必须**完全等于**角色文件去掉 `.md` 后的文件名（大小写、连字符、下划线全部敏感）。
- 不接受任何形式的模糊匹配、部分匹配、别名、拼写纠正。
- 不接受多个角色名同时加载（一次只能激活一个主角色）。
- `<任务名称>` 可选。三种合法形式由 agent 自动识别：
  1. **完整任务ID**：例 `01approveList.4.10.0`。
  2. **lowerCamelCase 任务名**：例 `approveList`，版本号默认走 `package.json`，任务名末尾如带 semver（`approveList 4.10.0`）则按其覆盖。
  3. **中文任务名**：例 `审批列表`，由 agent 翻译/概括成 lowerCamelCase；末尾如带 semver 则按其覆盖。
- 未传 `<任务名称>` 时，进入「回退查询最近任务」流程（见 Step 5B）。
- 子命令关键字 `switch`、`init` 必须**字面精确**匹配（区分大小写，`Switch` / `SWITCH` / `swich`、`Init` / `INIT` 均不算）。

每次 `/roleflowv2 <角色名> ...` 调用必须完成三件事，缺一不可：

1. **加载角色职责**（Step 2–4）
2. **解析/确认本次任务ID**（Step 5；新任务**必须同步写入 taskIndex.md**）
3. **定位工件存放目录**（Step 6）

`/roleflowv2 switch <任务名>` 只做一件事：在已注册的任务之间切换会话上下文，**角色保持不变**。

## 工作流（主命令）

### Step 1: 解析参数

从用户输入中提取 `<角色名>` 与 `<任务名称>`：

- 按首个空白拆分：第 1 段为 `<角色名>`，其余整段拼回为 `<任务名称（原始）>`。
- 第 1 段如果字面等于 `init` 或 `switch`，**不要**当作角色名 —— 改为读取并严格执行 skill 目录下对应子命令文档（`init` → `init.md`；`switch` → `switch.md`），不再走主命令 Step 2–7。除非用户实际输入了该关键字，否则**不要**预读这两个文档。
- 角色名前后空白字符要 trim，但中间字符原样保留。
- 任务名称两端 trim，中间空白原样保留。
- 如果用户只输入 `/roleflowv2`（连角色名都没有），**不要猜测**，直接执行 Step 2 列出可用角色，并提示"请通过 `/roleflowv2 <角色名> [任务名称]` 指定要加载的角色"。

### Step 2: 定位角色目录

按以下**优先级顺序**确定角色目录（命中即停止，不合并）。判定规则：依次 `ls` 检查每个候选目录是否存在，**第一个存在的目录即为生效目录**，不再继续往下查。

**项目实例层**（按从上到下顺序判定，全部相对于当前工作目录）：

1. `roleflow/context/roles/`
2. `docs/link-ai-prompt/roleflow/context/roles/`
3. `.vscode/link-ai-prompt/roleflow/context/roles/`
4. `docs/roleflow/context/roles/`
5. `.vscode/roleflow/context/roles/`

**全局原型层**（仅当上面 5 个项目实例层目录全部不存在时使用）：

6. `/Users/aaron/code/roleflow/roles/`

如果以上 6 个目录全部不存在，告知用户"未找到任何 roleflow 角色目录"并停止。

> **注意**：项目实例层一旦命中就**完全覆盖**全局原型层与其他项目实例层候选目录，不做合并、不做补全。
>
> **同时记下**生效角色目录所对应的「项目根前缀」（roles/ 的父目录的父目录，例：项目实例层 2 命中 → 前缀为 `docs/link-ai-prompt/roleflow/`；全局原型层命中 → 没有项目前缀，见 Step 6 处理）。这个前缀决定 Step 6 的工件目录路径，也是 switch 子命令定位 taskIndex.md 的依据。

### Step 3: 精确匹配角色文件

在选定目录下查找文件 `<角色名>.md`：

- **命中（恰好一个文件）**：进入 Step 4。
- **未命中**：执行下方"未命中处理"流程。

**禁止做的事**：
- ❌ 不允许做大小写不敏感匹配（例如 `Builder` 不会命中 `builder.md`）。
- ❌ 不允许做前缀/后缀/包含匹配（例如 `build` 不会命中 `builder.md`）。
- ❌ 不允许做拼写纠正（例如 `bulider` 不会命中 `builder.md`）。
- ❌ 不允许在用户给出歧义输入时自动选择"最接近的一个"。

#### 未命中处理

1. 用 `ls <选定目录>/*.md` 列出该目录下所有可用角色文件。
2. 输出格式如下：

   ```
   未找到角色 "<用户输入>"。当前 <目录路径> 下可用的角色：
   - archivist
   - builder
   - chat
   - ...

   请使用 /roleflowv2 <角色名> [任务名称] 重新指定（角色名需精确匹配，区分大小写）。
   ```

3. **停止执行**，等待用户重新输入。不要自作主张加载任何角色。

### Step 4: 解析版本号

按以下顺序确定 `[版本号]`：

1. **任务名称中显式带 semver**：从用户提供的 `<任务名称>` 中提取尾部 `\d+\.\d+\.\d+` 子串（如 `审批列表 4.10.0` → `4.10.0`，`01approveList.4.10.0` → `4.10.0`）。命中则记为 `[版本号]`，并从任务名称中去掉该尾部（用于后续解析任务主体）。
2. **package.json**：读取当前工作目录的 `package.json`，取 `version` 字段。
3. **都没有**：向用户索要版本号，禁止瞎编。

### Step 5: 解析/确认任务ID

#### Step 5A: 用户提供了任务名称

按下表分类处理：

| 用户输入主体形态 | 识别规则 | 处理 |
|------------------|---------|------|
| **完整任务ID** | 形如 `^\d{2}[a-z][a-zA-Z0-9]*\.\d+\.\d+\.\d+$` | 直接采纳，仅校验格式；不再重新翻译，不再生成新序号 |
| **lowerCamelCase 任务名** | 形如 `^[a-z][a-zA-Z0-9]*$`，全 ASCII | 跳过翻译；走「先查后建」匹配流程（下方 §匹配流程） |
| **中文任务名** | 包含任意非 ASCII 字符 | 先翻译/概括成 2–5 个 lowerCamelCase 英文单词（越少越好），再走「先查后建」匹配流程 |
| **混合 / 无法识别** | 既不像中文也不像合法 camelCase / 完整ID | 向用户澄清"我没法判断这是任务名还是任务ID，请确认"，给出 2–3 个候选解释 |

##### 匹配流程

1. **定位 tasks/ 目录**：紧跟 Step 2 命中的角色目录所属根，把 `<前缀>/context/roles/` 替换为 `<前缀>tasks/`（即对应位置的 `tasks/[版本号]/`）。
   - 项目实例层 1 命中（`roleflow/context/roles/`）→ tasks 落 `roleflow/tasks/[版本号]/`
   - 项目实例层 2 命中（`docs/link-ai-prompt/roleflow/context/roles/`）→ tasks 落 `docs/link-ai-prompt/roleflow/tasks/[版本号]/`
   - 项目实例层 3 → `.vscode/link-ai-prompt/roleflow/tasks/[版本号]/`
   - 项目实例层 4 → `docs/roleflow/tasks/[版本号]/`
   - 项目实例层 5 → `.vscode/roleflow/tasks/[版本号]/`
   - 全局原型层命中 → 没有项目实例层 tasks 目录，按 Step 6 兜底询问用户。

2. **查已有匹配**：在 `tasks/[版本号]/` 下列目录，按正则 `^\d{2}<lowerCamelCaseName>\.\d+\.\d+\.\d+$` 匹配。
   - **恰好命中一个**：取该任务ID，进入 §确认。
   - **命中多个**（同名重复，理论上不该发生）：把全部候选念给用户，让其选一个。
   - **未命中**：进入「新建」。

3. **新建任务ID**：
   - 读 `tasks/[版本号]/` 下所有目录名，提取前缀 `\d{2}`，取最大值 + 1，左侧补零成 2 位 → `[任务序号]`。目录不存在或为空，则 `01`。
   - 拼接：`[任务序号][lowerCamelCaseName].[版本号]`。
   - **新建后必须立刻注册到 `tasks/[版本号]/taskIndex.md`**（追加一行；文件不存在则创建表头）。注册时机、字段、格式见角色公共原型 `/Users/aaron/code/roleflow/roles/base/common.md` §10（生效角色目录的 `common.md` 如有项目补充，一并遵循）。Agent 须在 §确认 步骤里同时把"将注册到 taskIndex.md"念给用户。

##### §确认（统一确认 UX）

- 把完整任务ID 念给用户，**一律使用如下格式**，等待用户确认：

  ```
  本次任务ID 推断为：<任务ID>
  - 角色：<角色名>（来源：<项目实例层 / 全局原型层>）
  - 任务来源：<复用已有 / 新建>
  - 工件目录：<tasks/[版本号]/[任务ID]/ 的完整项目根相对路径>
  - 新任务注册：<将追加到 tasks/[版本号]/taskIndex.md / 已在 taskIndex.md 中，无需注册>
  确认请回复"确认"或直接给出后续指令；若需修改任务ID，请直接说明。
  ```

- 用户确认后，**新建任务**分支立即写 taskIndex.md（详见 common.md §10）。
- **本次会话内同一任务ID 不再重复确认**：后续 `/roleflowv2 <其他角色>` 切换、`/roleflowv2 switch` 子命令、或角色文件本身的"任务ID 推断流程"，只要会话上下文已有确认过的任务ID，**一律继承**，不再问用户。
- 用户主动给出新的 `<任务名称>` 时，重新走 Step 5。

#### Step 5B: 用户未提供任务名称

按以下顺序，**依次只查**项目实例层 5 个 tasks 目录的对应位置（与 Step 2 同套层次，但**独立**判断 tasks 子目录是否存在，**不**强制跟随 Step 2 命中的层级）：

1. `roleflow/tasks/[版本号]/`
2. `docs/link-ai-prompt/roleflow/tasks/[版本号]/`
3. `.vscode/link-ai-prompt/roleflow/tasks/[版本号]/`
4. `docs/roleflow/tasks/[版本号]/`
5. `.vscode/roleflow/tasks/[版本号]/`

在**第一个存在且非空**的目录里，取**最近任务**（按目录名前缀 `\d{2}` 排序取最大者，并列时按 mtime 取最新）作为候选。

向用户确认：

```
未提供任务名称。从 <匹配路径> 中找到最近任务：<候选任务ID>
是否继续使用该任务？
- 回复"是"→ 继续使用该任务ID
- 回复"否"→ 请重新调用 /roleflowv2 <角色名> <任务名称>
```

- 5 个目录全部不存在或全部为空：直接告诉用户"当前未找到任何已有任务，请通过 `/roleflowv2 <角色名> <任务名称>` 提供任务名称"，**停止执行**，不要自行造新 ID。

### Step 6: 确定工件存放目录

最终工件目录为：

```
<tasks 根>/[版本号]/[任务ID]/
```

其中 `<tasks 根>` 的选择规则：

- **Step 5A 命中已有任务**：直接使用 Step 5A §匹配流程 §1 中定位到的 tasks 根（跟随 Step 2 命中的角色目录根）。
- **Step 5A 新建任务**：同上，跟随 Step 2 命中的角色目录根。若 Step 2 命中的是全局原型层（无项目实例层目录），**停下来询问用户**该项目希望把任务工件放到哪个 5 层路径下，禁止自行决定。
- **Step 5B 命中最近任务**：使用 Step 5B 命中的那一层目录。

不存在的子目录（如 `tasks/[版本号]/[任务ID]/`）由后续落盘工件的角色文件自行 `mkdir -p` 创建；本 skill **不预先创建**，避免遗留空目录。

### Step 7: 加载并应用角色

1. 用 `Read` 工具读取角色文件 `<选定目录>/<角色名>.md` 的完整内容。
2. 同时检查并读取 `<选定目录>/common.md`（如果存在）—— 它是所有角色共享的基础协作原则，必须叠加到当前角色之上。若该文件不存在（如命中全局原型层），改读 `<选定目录>/base/common.md`（全局原型层的公共规范位于 `base/` 子目录）。
3. 向用户输出**简短确认**（不超过 5 行），格式如下：

   ```
   已加载角色：<角色名>（来源：<项目实例层 N / 全局原型层>）
   职责摘要：<从角色文件首段提炼的一句话>
   本次任务：<任务ID>（<复用已有 / 新建 / 来自最近任务回退>）
   工件目录：<完整项目根相对路径>
   后续所有任务将按此角色的规范执行。
   ```

4. 在后续对话中：
   - 把角色文件 + `common.md` 的规则视为**最高优先级行为约束**，凌驾于一般默认行为之上。
   - 把上面确认的 `<任务ID>` 与 `<工件目录>` 作为**会话级共享上下文**，所有后续工件落盘命名按此执行；角色文件中"任务ID 推断流程"在已确认的会话内**不再触发**。
   - 当角色规则与项目 CLAUDE.md 冲突时，**优先遵循角色规则**，并在必要时向用户说明冲突点。
   - 当角色规则与用户即时指令冲突时，停下来询问，不要自行选择。

## 子命令（按需加载）

以下两个子命令的完整流程**不在本文件内联**，仅当用户实际调用时，才读取并严格执行 skill 目录下对应文档；不调用就不读。

| 子命令 | 触发 | 文档 | 作用 |
|--------|------|------|------|
| `init` | `/roleflowv2 init` | `init.md` | 在当前目录脚手架出 roleflow(v2) 骨架（context + tasks 两层；tasks 留空；roles 从全局原型层拷入并写入 v2 common.md） |
| `switch` | `/roleflowv2 switch <任务名>` | `switch.md` | 在已注册任务之间切换会话上下文，**当前角色保持不变** |

- 关键字 `init` / `switch` 必须**字面精确**匹配（见 §调用语法）；拼错或大小写不符则回退主命令按角色名处理。
- 两个子命令各自的边界与示例都在对应文档内，本文件不重复。

## 边界与禁止事项

- **不可同时激活两个角色**：如果用户在已加载某个角色后再次执行 `/roleflowv2 <新角色> [任务名称]`，视为切换角色 —— 丢弃旧角色规则，按新角色规则执行，并明确告知用户"已从 <旧角色> 切换到 <新角色>"。
  - **任务ID 处理**：用户未在新调用中给 `<任务名称>` 时，**继承当前会话已确认的任务ID 与工件目录**，不再问用户；用户重新给了 `<任务名称>` 时，按 Step 5 重新解析并确认。
- **不可静默加载**：每次加载都必须输出 Step 7 的确认信息（含任务ID 与工件目录），让用户清楚当前激活的角色、任务、落盘位置；子命令（init / switch）的确认输出见各自文档。
- **不可篡改角色文件**：本 skill 只负责加载，不负责创建、编辑、删除角色文件。如果用户要求修改角色定义，引导其手动编辑 `roleflow/context/roles/` 或 `/Users/aaron/code/roleflow/roles/` 下的文件。
- **不可跨目录混用**：一次加载只读取一个目录下的文件，不会从全局原型层补全项目实例层缺失的角色。
- **不可瞎编任务ID**：任何无法从用户输入、package.json、已有任务目录中推断的关键段（版本号 / 任务序号 / 任务主体），必须向用户索要，禁止造数据。
- **不可跳过任务ID 确认**：Step 5 §确认 与 Step 5B 的"是否继续"两类确认必须输出，除非会话上下文已经确认过同一任务ID。
- **不可跳过 taskIndex.md 注册**：Step 5A 新建任务分支必须在 §确认 后、首份工件落盘前完成 taskIndex.md 注册。详见 common.md §10。
- **子命令边界另见各自文档**：`init` / `switch` 的专属边界与示例分别在 `init.md` / `switch.md`，本文件不重复（含 switch 关键字字面精确、switch 不动角色等规则）。

## 示例

### 示例 1：完整三件事（中文任务名 + 命中已有任务）

用户：`/roleflowv2 builder 审批列表`

执行：
1. 解析：角色 `builder`，任务名称 `审批列表`。
2. 角色目录：项目实例层 2 `docs/link-ai-prompt/roleflow/context/roles/` 命中 → 读 `builder.md` + `common.md`。
3. 版本号：任务名内无 semver → 读 `package.json` → `4.10.0`。
4. 中文→camelCase：`审批列表` → `approveList`。
5. 匹配：在 `docs/link-ai-prompt/roleflow/tasks/4.10.0/` 下查 `^\d{2}approveList\.4\.10\.0$` → 命中 `01approveList.4.10.0`（已有，无需注册到 taskIndex.md）。
6. 工件目录：`docs/link-ai-prompt/roleflow/tasks/4.10.0/01approveList.4.10.0/`。
7. 输出：

   ```
   已加载角色：builder（来源：项目实例层 2）
   职责摘要：根据 Spec 编写实现代码，并维护任务状态。
   本次任务：01approveList.4.10.0（复用已有）
   工件目录：docs/link-ai-prompt/roleflow/tasks/4.10.0/01approveList.4.10.0/
   后续所有任务将按此角色的规范执行。
   ```
