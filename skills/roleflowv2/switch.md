# Roleflowv2 子命令：switch

> 本文件**仅在用户调用 `/roleflowv2 switch <任务名>` 时**由 SKILL.md 按需读取并严格执行，平时不要预加载。
> 作用：在**当前会话已加载角色不变**的前提下，把任务上下文切换到另一个任务。目标任务**已在 taskIndex.md 注册**时直接切换；**任务目录已存在但 taskIndex.md 里没有**时，**先补登 taskIndex.md、再切换**（见 Step S5B / S6.5）。

## 工作流

### Step S1: 解析

- 用户输入：`/roleflowv2 switch <查询串>`。
- 用首个空白把 `switch` 与查询串分开；查询串两端 trim，中间保留原样。
- 关键字 `switch` 必须**字面精确**匹配（区分大小写）。若用户输入 `Switch` / `SWITCH` / `swich` 等，**不**进入 switch 流程 —— 这时回到主命令解析：尝试把首段当作 `<角色名>` 走 SKILL.md Step 2–3；按角色名也匹不上则提示"未找到角色 / 不是合法的 switch 关键字"，停止。
- 查询串为空：列出当前 taskIndex.md 全表，提示"请通过 `/roleflowv2 switch <任务名>` 指定"，停止。

### Step S2: 校验前置

- **会话内必须已加载角色**（即此前已成功执行过 `/roleflowv2 <角色名> ...`）。否则提示：

  ```
  尚未加载任何角色。请先用 /roleflowv2 <角色名> [任务名称] 加载角色，再调用 switch。
  ```

  停止。

### Step S3: 解析版本号

- 默认读 `package.json` 的 `version` 字段。
- 查询串末尾如带 semver，按其覆盖（并从查询串里去掉该尾段）。
- 都没有：向用户索要版本号，禁止瞎编。

### Step S4: 定位 taskIndex.md

- 跟随当前会话已确定的 `<tasks 根>`（即上次主命令命中的根）。
- 路径：`<tasks 根>/[版本号]/taskIndex.md`。
- **文件不存在**：先 `ls <tasks 根>/[版本号]/`，看有没有符合任务ID 格式（`^\d{2}[a-z][a-zA-Z0-9]*\.\d+\.\d+\.\d+$`）的目录。
  - **有**：**不要停**——taskIndex.md 缺失但任务确实存在，直接进入 **Step S5B** 做目录兜底匹配，命中后由 Step S6.5 创建文件、写表头并补登。
  - **没有**（版本目录不存在，或目录下没有任何合法任务目录）：

    ```
    <版本号> 版本尚无任务索引（taskIndex.md 不存在），该版本目录下也没有任何已建任务目录。请先用 /roleflowv2 <角色名> <任务名称> 注册任务后再切换。
    ```

    停止。

### Step S5: 模糊匹配

- 解析 taskIndex.md 表格，逐行抽取 `任务ID`、`中文名` 两列（其余字段不参与匹配）。
- 把查询串和这两列同时做**小写化**（中文字符不受影响），按**子串包含**判定：查询串作为子串、目标列作为母串，命中即算。
  - 例：查询串 `defi` 同时命中 `02defiIndexdbCache.4.10.0` 和 `04defiGaClick.4.10.0`。
  - 例：查询串 `授权` 命中 `01approvalList.4.10.0`（中文名"授权列表"）。
  - 例：查询串 `approval` 命中 `01approvalList.4.10.0`（任务ID 含 `approval`）。
- 命中集合：
  - **恰好 1 条** → 进入 Step S7。
  - **0 条** → **不要立即停止**，先进入 **Step S5B** 做目录兜底匹配（taskIndex.md 可能漏登了已经存在的任务目录）。
  - **多于 1 条** → 进入 Step S6 让用户选。

### Step S5B: 目录兜底匹配（taskIndex 未命中 / 文件缺失时）

taskIndex.md 与实际目录不一致是常态（手动建目录、迁移、漏登都会造成）。本步的前提是：**任务目录是事实，taskIndex.md 只是索引**——目录在就允许切换，索引缺了就补。

- 列出 `<tasks 根>/[版本号]/` 下所有匹配 `^\d{2}[a-z][a-zA-Z0-9]*\.\d+\.\d+\.\d+$` 的**目录名**（目录名即任务ID）。排除 `taskIndex.md` 等文件。
- 用与 Step S5 相同的规则匹配：查询串与目录名同时**小写化**后按**子串包含**判定。此处**没有中文名可匹配**（中文名只存在于 taskIndex.md），所以中文查询串在本步通常匹配不到——这是正常的，按 0 条处理。
- 命中集合：
  - **恰好 1 条** → 进入 **Step S6.5** 先补登，再 Step S7 切换。
  - **多于 1 条** → 进入 Step S6 让用户选，候选行尾标注 `（未注册）`；用户选定后回到本步，再走 S6.5。
  - **0 条** → 到此才算真的找不到，输出下面内容后**停止**：

    ```
    查询 "<查询串>" 在 taskIndex.md 和 <版本号> 的任务目录里都没有命中。

    taskIndex.md 已注册的任务：
    - <任务ID> — <中文名>
    - …

    目录存在但未注册的任务：
    - <任务ID>
    - …

    请用更精确的任务ID 子串重新指定，或用 /roleflowv2 <角色名> <任务名称> 新建任务。
    ```

    （两份清单都为空时，相应小节写"（无）"。）

### Step S6: 候选去歧义（多命中分支）

输出：

```
查询 "<查询串>" 命中多个任务，请回复任务ID 或更精确的子串：
- 01approvalList.4.10.0 — 授权列表
- 04defiGaClick.4.10.0 — defi GA 点击异常
- …
```

停止等用户回复。用户回复任务ID 或更精确子串后回到 Step S5 重判。

### Step S6.5: 补登 taskIndex.md（仅 Step S5B 命中时执行）

**只有**经 Step S5B 命中（目录存在、taskIndex.md 无记录）才走本步；Step S5 直接命中的任务**不重写任何行**。

字段与格式严格按角色公共原型 `common.md` §10（生效角色目录的 `common.md` 如有项目补充，一并遵循）：

| 列 | 本步取值 |
|---|---|
| 任务ID | 目录名原样，不重新生成序号 |
| 中文名 | 按下面「中文名来源」确定 |
| 状态 | `active` |
| 创建日期 | **该任务目录的创建/修改日期**（`stat -f "%SB" -t "%Y-%m-%d" <目录>`，取不到则用 `%Sm`）。**不要用今天的日期冒充创建日**；实在取不到才用今天，并在输出里说明 |
| 描述 | 一句话概括（≤ 20 字），来源同中文名；推断不出就写 `-`，**禁止编造** |

**中文名来源**（按顺序，第一个可得的即采用）：

1. 任务目录内工件的一级标题（如 `spec.md` / `prd*.md` 的首个 `# ` 标题）；
2. 用户本次输入的查询串——**仅当它是中文**时；
3. 都取不到 → **停下来问用户**：

   ```
   任务 <任务ID> 的目录已存在，但 taskIndex.md 里没有记录，需要补登。
   目录里没有可推断中文名的工件，请给一个中文名（描述可选）：
   ```

   得到回复后再写。**禁止用任务ID 音译、也禁止瞎编中文名。**

写入规则：

- taskIndex.md **不存在**：先 `mkdir -p <tasks 根>/[版本号]/`，创建文件并写表头（`# Task Index v[版本号]` + 表头行 + 分隔行），再追加任务行。
- taskIndex.md **已存在**：只追加到表尾，**不重排、不改动已有行**。
- 补登**只写这一条命中的任务**；同目录下其它未注册任务**不顺带补登**（避免一次 switch 产生大量无中文名的行）。可在 Step S7 输出里提示还有几个未注册。
- 本步**不创建任务目录、不新建任务**：目录必须已经存在，这是与主命令 Step 5A「新建任务」的根本区别。

### Step S7: 切换并告知

- 把会话级 `<任务ID>` 和 `<工件目录>` 替换为命中任务的；**当前角色保持不变**。
- 输出切换结果（不超过 5 行，仅告知，不等待回复）：

  ```
  已切换到任务：<任务ID>
  - 中文名：<中文名>
  - 角色：<当前角色>（继承自上次加载，未变更）
  - 工件目录：<完整项目根相对路径>
  - taskIndex：<已注册 / **本次补登**（原先缺失）>
  后续工件按此任务落盘。
  ```

- 经 Step S6.5 补登的，`taskIndex` 行必须写明是本次补登，并在其后补一行说明（仅在有内容时输出）：

  ```
  说明：该任务目录已存在但未在 taskIndex.md 注册，已补登一行（创建日期取目录日期 <YYYY-MM-DD>）。
  该版本还有 <N> 个目录未注册：<任务ID>、<任务ID>…
  ```

## 边界与禁止事项（switch 专属）

- **switch 不动角色**：`/roleflowv2 switch <任务名>` **只换任务**，不换角色。如需同时换角色，先 switch 再 `/roleflowv2 <新角色>`（不带任务名即可继承新任务）。
- **不可对 `switch` 关键字做模糊匹配**：仅 `<任务名>` 模糊，关键字本身字面精确。
- **不可静默切换**：必须输出 Step S7 的切换结果（含任务ID 与工件目录）；该输出仅告知，不等待确认。
- **目录是事实，索引是索引**：taskIndex.md 没有记录**不等于**任务不存在。只要 `<tasks 根>/[版本号]/` 下有对应目录，就走 Step S5B 兜底匹配并在 Step S6.5 补登，然后正常切换；**不得**以"未注册"为由拒绝切换。
- **补登只补命中的那一条**：一次 switch 最多向 taskIndex.md 追加一行，且必须是本次切换命中的任务；其余未注册目录只在输出里提示，不批量补登。
- **switch 永不创建任务**：本子命令只补索引，**不创建任务目录、不生成新任务ID、不改已有行**。目录不存在时按 Step S5B 的 0 命中处理并停止，绝不为不存在的目录补登。
- **中文名不许编造**：补登时推断不出中文名就停下来问用户（Step S6.5），不得用任务ID 音译或自行臆造。

## 示例

### 示例 A：中文模糊匹配（单命中）

会话内已加载 `/roleflowv2 builder 审批列表`（任务 `01approveList.4.10.0`）。

用户：`/roleflowv2 switch 观察钱包`

执行：
1. 关键字 `switch` 字面命中。
2. 角色已加载（builder），版本号 `4.10.0`。
3. 读 `docs/link-ai-prompt/roleflow/tasks/4.10.0/taskIndex.md`。
4. 子串包含 `观察钱包`（小写化）扫描两列：命中 1 条 `03watchWalletDapp.4.10.0`（中文名"观察钱包连接网站"）。
5. 切换并输出：

   ```
   已切换到任务：03watchWalletDapp.4.10.0
   - 中文名：观察钱包连接网站
   - 角色：builder（继承自上次加载，未变更）
   - 工件目录：docs/link-ai-prompt/roleflow/tasks/4.10.0/03watchWalletDapp.4.10.0/
   后续工件按此任务落盘。
   ```

### 示例 B：多命中去歧义

用户：`/roleflowv2 switch defi`

执行：
1. 关键字命中。
2. 在 taskIndex.md 中子串包含 `defi` → 命中 2 条：`02defiIndexdbCache.4.10.0`、`04defiGaClick.4.10.0`。
3. 输出：

   ```
   查询 "defi" 命中多个任务，请回复任务ID 或更精确的子串：
   - 02defiIndexdbCache.4.10.0 — defi添加indexDB
   - 04defiGaClick.4.10.0 — defi GA 点击异常
   ```

4. 等用户回复 → 再走一次 Step S5。

### 示例 C：关键字拼错（不进入 switch）

用户：`/roleflowv2 Switch 授权列表`

执行：
1. 关键字 `Switch` 与字面 `switch` 不等（大小写不同）→ **不进入** switch 流程。
2. 回退到主命令：把首段 `Switch` 当作角色名 → 在当前角色目录下找 `Switch.md` → 未命中。
3. 列出可用角色，提示用户重新调用。**不会**因为"看着像 switch"而自动模糊纠正。

### 示例 D：目录已存在但 taskIndex 未注册（补登后切换）

会话内已加载 `/roleflowv2 builder 审批列表`。`docs/link-ai-prompt/roleflow/tasks/4.10.0/` 下有目录 `05gasFreeSend.4.10.0`（此前手动建的 / 迁移过来的），但 taskIndex.md 里没有这一行。

用户：`/roleflowv2 switch gasFree`

执行：
1. 关键字 `switch` 字面命中；角色已加载（builder），版本号 `4.10.0`。
2. Step S5 在 taskIndex.md 两列里扫 `gasfree` → **0 命中**，不停止。
3. Step S5B 扫目录：`05gasFreeSend.4.10.0` 小写化后含 `gasfree` → **恰好 1 条**。
4. Step S6.5 补登：读 `05gasFreeSend.4.10.0/` 下工件，`spec.md` 首行标题为 `# 免 Gas 转账`→ 中文名取"免 Gas 转账"；`stat` 得目录创建日期 `2026-09-15`；追加一行到 taskIndex.md 表尾。
5. Step S7 输出：

   ```
   已切换到任务：05gasFreeSend.4.10.0
   - 中文名：免 Gas 转账
   - 角色：builder（继承自上次加载，未变更）
   - 工件目录：docs/link-ai-prompt/roleflow/tasks/4.10.0/05gasFreeSend.4.10.0/
   - taskIndex：本次补登（原先缺失）
   后续工件按此任务落盘。
   说明：该任务目录已存在但未在 taskIndex.md 注册，已补登一行（创建日期取目录日期 2026-09-15）。
   ```

> 若第 4 步在目录里找不到可推断中文名的工件，且查询串 `gasFree` 不是中文 → 停下来问用户要中文名，拿到后再写，**不得**音译成"免 Gas 发送"之类。
