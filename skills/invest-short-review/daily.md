# daily 子命令 · 关注列表每日批量复盘

`invest-short-review` 的批量模式：读取**关注列表文件**里的全部标的，**按市场分组**逐只跑一遍完整复盘流程，把每只的结论压缩成 **500~1000 字**，汇总成**一份按「日期-序号」命名的 md**（一天可跑多次，每次新开一份，不覆盖）。

> 与主流程的关系：`daily` **不是新方法论**，只是「读列表 → 按市场分组 → 对每只执行 SKILL.md + 对应市场文件的流程 → 收敛成一节 → 拼成一份日报」的编排层。归因、多派会诊、必须明确表态等所有硬约束，`daily` 里**一条都不放宽**。

---

## 调用方式

```
/invest-short-review daily            # 三个市场全跑
/invest-short-review daily A股        # 只跑某个市场
/invest-short-review daily 币圈
```

市场名接受：`A股`/`a股`/`ashare`、`美股`/`us`、`币圈`/`加密`/`crypto`（大小写不敏感）。其它等价形式：`用 invest-short-review 跑 daily`、`调用 invest-short-review daily，只跑前 3 只`。

同样受主 SKILL.md 的**显式调用**硬约束：用户没点名 skill、只是说「今天大盘怎么样」「帮我看看关注的票」，**不触发** `daily`。

### 可选参数

| 参数 | 说明 | 默认 |
|---|---|---|
| 市场 | 只跑某一个市场 | 全部三个 |
| 时间区间 | 每只标的的复盘窗口 | 各市场文件的默认（股票近 5 交易日；加密近 7 天） |
| 关注列表路径 | 输入文件 | `/Users/aaron/workspace/个人/投资分析记录/关注列表.md` |
| 输出目录 | 日报存放位置，**按年份分目录** | `/Users/aaron/workspace/个人/投资分析记录/<YYYY>record/` |
| 只跑子集 | 如「只跑光模块那几只」「只跑前 3 只」 | 全部 |
| `--keep-single`（口头说「每只也单独出报告」即可） | 额外把每只的完整长报告写到 `/Users/aaron/workspace/llmWikis/investWiki/others/research/` | **关闭**，`daily` 默认只产出汇总日报 |

## 执行步骤

### 0. 每次都重新读关注列表（硬要求）

```
Read /Users/aaron/workspace/个人/投资分析记录/关注列表.md
```

- **禁止**使用上一次运行缓存的名单、也禁止凭记忆列标的。该文件会被用户随时增删改，**每次 `daily` 必须现场重读**。
- **文件结构**：二级标题 `## A股` / `## 美股` / `## 币圈` 分市场；每段下面 `### 关注列表` 里的条目要跑，`### 以下内容仅备选，不用分析` 里的**不跑**。
- 解析规则：取 `- ` 开头的列表项作为标的；忽略标题行、空行、注释行（`>`、`<!-- -->`）、以及「暂无」这类占位说明。
- **标的所属市场由它所在的二级标题决定**，不靠自己猜；某段为空就跳过该市场。
- 条目可能是**名称**（「中际旭创」「以太坊」）、**代码/符号**（「300308」「NVDA」「ETH」），或混写；都要能吃下。名称可能是简写/俗称（如「长飞光纤光缆」实为「长飞光纤」601869）——用 `WebSearch` 核对，**别张冠李戴**。
- **不要停下来等用户确认**：解析完把「市场 → 名称 → 代码」映射打到终端知会一声就直接开跑，`daily` 是无人值守的批量命令。映射若有错，用户看到输出自会打断。
- 唯一的例外是**真解析不出来**：某条目搜出多个同名标的、或查不到对应代码时，**别猜**——记为失败跳过、继续跑其余标的，在日报开头的「本次未完成」里写清原因。
- 列表为空 / 文件不存在 → 直接告知用户并停止，不要自己编一份名单。

### 1. 逐只执行主流程

对名单里**每一只**标的，按 `SKILL.md` 的共用骨架 + **它所属市场的市场文件**（`a-share.md` / `us-stock.md` / `crypto.md`）跑完整流程：解析输入 → 取数识别异动 → 联动对比 → 逐个异动联网查因 → 平静期简报 → forSkills 会诊 → 明确投资建议。

**批量模式下的执行注记：**

- **开跑前先取真实时刻**（不许凭 `currentDate` 推、不许估）：

  ```bash
  date "+%Y-%m-%d %H:%M %Z"
  ```

  记为**分析开始时刻**；每只标的跑完各记一次该标的的**分析时刻**；全部跑完再取一次作为**分析结束时刻**。三者都精确到**分钟**，写进日报。
- **按市场分组串行**：先跑完 A股，再美股，再币圈（只跑某个市场时就只跑那一段）。开跑前先告知用户预计要跑几只、分布在哪几个市场。
- **每个市场的共享查询只做一次**：A股/美股的板块与海外映射（当日大盘、SOX、NVDA 隔夜、半导体 ETF）、币圈的大盘与情绪（BTC/ETH 走势、恐惧贪婪、ETF 流、全网爆仓）在该市场开始时查一次，段内各标的共用，避免重复搜索。
- **同窗口同代码不重复取数**：名单内部常同属一条链或同一生态，已拉过的对比标的行情直接复用。
- **单只失败不中断**：某只取数失败或代码解析不了，记下原因，该节写「本次未取到数据：<原因>」，继续下一只。全部跑完在日报开头汇总失败清单。

### 2. 把每只标的收敛成 500~1000 字

每只在日报里占**一个三级小节**，正文 **500~1000 字**（不含表头/链接列表）。这是压缩，不是删减——下列要素**必须全在**：

- 近窗涨跌幅与是否触发异动阈值（**按该市场的阈值**：股票单日≥±5%/累计≥±10%；加密单日≥±8%/累计≥±20%）
- 主驱动归因分层（按该市场文件的层级），能量化超额就量化
- 关键异动日的催化及证据（带链接与日期），**查无催化就直说「未找到明确催化」**
- 该市场的映射维度里跟本标的直接相关的那一两条（产业链/海外｜链上/衍生品）
- 多派会诊的**结论**（哪派主导、哪派让位），不用铺开整张矩阵
- **明确的投资建议**：方向＋力度＋操作要点＋改判条件＋置信度
- **该标的的分析时刻**（精确到分钟）：批量跑一轮可能横跨一两个小时，第 1 只和第 10 只面对的盘口完全不同

字数不够多半是漏了归因层或改判条件；超过 1000 字就把逐日流水账压成结论。

写完本节后，再从这一节里抽一行**一句话速览**（含明确建议），汇总到日报最上面，写法见 §3 和模板。

### 3. 写日报

- 输出目录：**按年份分目录** `/Users/aaron/workspace/个人/投资分析记录/<YYYY>record/`，年份取 system `currentDate` 的年。
  - 年份目录**不存在就先建**：`mkdir -p /Users/aaron/workspace/个人/投资分析记录/<YYYY>record`
  - **禁止**往上一级的 `投资分析记录/` 根目录写日报；那里只放 `关注列表.md` 等输入文件。
- 文件名：**`<YYYY-MM-DD>-<序号>.md`**，如 `2026record/2026-09-18-1.md`。**一天可能跑多次，每次都写新文件，永不覆盖**。
  - 序号取法：先列当年目录 `ls /Users/aaron/workspace/个人/投资分析记录/<YYYY>record/<YYYY-MM-DD>-*.md 2>/dev/null`，取最大序号 +1；一个都没有则从 **1** 起。序号不补零、不跳号、不复用，只在当年目录内统计。
  - **只跑了一个市场也用同样的文件名规则**，在元信息里写明「本次只跑 <市场>」。
- **必须写明分析时间，精确到分钟**（硬要求）：
  - 元信息行写 `分析时间：<YYYY-MM-DD HH:MM> ~ <HH:MM>（<时区>）`；
  - 每只标的的建议行末尾带 `｜ 分析时刻 <HH:MM>`；
  - 时间一律取 `date` 的真实输出，**禁止写「上午」「盘中」「约 10 点」，禁止事后估算或补编**；
  - 盘中跑的还要标注**行情数据截止时刻**（最后一根 K 线是哪天收盘 / 是否盘中快照）。加密 24/7，写 UTC 日切与最后一根是否进行中。
- **日报最上面必须有「一句话速览」**：位置在元信息块之后、「今日总览」之前，**按市场分组**，组内顺序与下文各节一致。
  - 每只标的**一行**，格式：`- **<简称>（<代码/符号>）**：<区间涨跌> ｜ <一句话主因> → **<建议>（<力度>）｜置信度 <高/中/低>**`
  - **必须带明确建议**（买/加/持/减/清/观望 + 力度 + 置信度），不许只写涨跌不表态；
  - 主因只留最关键的一条，**不摆证据、不放链接**，整行 60 字以内；
  - 取数失败的也占一行，写「本次未取到数据：<原因>」。
- 小节顺序：**A股 → 美股 → 币圈**，每个市场内部按关注列表里的顺序。
- 因为不覆盖，**无需任何确认**：直接写新序号文件，跑完把完整路径告诉用户。
- 同一天的多份日报各自独立完整，但可在开头注明「本日第 N 次运行，上一份：`<YYYY-MM-DD>-<N-1>.md`」。

## 注意事项

- **市场别串**：每只标的必须按它所在段落的市场跑对应市场文件——阈值、脚本、对比对象、镜头权重都不同。拿股票阈值跑币、或拿 A股脚本跑美股 ticker，都是硬错误。
- **时间戳必须真实**：分析时间来自 `date` 实测，精确到分钟，起止与每只时刻缺一不可。同一标的 10:15 和 14:40 的建议可能相反。
- **日报一律落在当年目录**：`<YYYY>record/` 是唯一合法输出位置，跨年自动切到新目录（先 `mkdir -p`）。
- **名单永远以文件为准**：`关注列表.md` 是唯一事实源，用户改了文件下次跑就自然生效；skill 侧不留任何硬编码名单。
- **不许为了赶进度跳过联网查因**：宁可告诉用户「名单太长，本轮先跑前 N 只」，也不要给一节没有证据、靠推测编出来的归因。
- **必须逐只表态**：每一节都要落到明确建议，不许出现「建议观察，仅供参考」式的整节回避（「观望」是合法表态，但要给出观望条件与改判触发点）。
- **速览、总览表、各节建议三处必须一致**：速览是对各节结论的压缩，不是重写。三处出现分歧时以各节正文为准并立刻改正。
- **非科技股 / 稳定币**：名单里混入非科技股或稳定币时，按对应市场文件的「适用范围」提示用户，仍可跑但标注维度弱化。
