# Dota2 真实消耗 + 健康预算 + 天梯进度（dota2-playtime）

三件事一次给齐：① 玩 Dota2 的**真实消耗时间**，② 对照**周时长预算**的健康评判，③ **天梯上分进度**。

**① 真实消耗时间 = Σ每局（对局时长 duration + 选人时间 + 匹配/赛后等额外开销）**
> - **对局时长**：OpenDota 每局 `duration` 相加（游戏内 0:00 到结束）。
> - **选人时间**：每局固定 **默认 90 秒**（天梯 All Pick 草选；`--pick-seconds` 可调）。
> - **匹配/赛后等**：每局固定 **默认 180 秒**（排队 + 赛后结算/复盘等不好精确统计的时间；`--overhead-seconds` 可调）。

**② 健康时长预算（按自然周、针对真实消耗时间）**
> **2026-08-17 这一周起启用 Plan B 奖励**：`当周有效时限 = 基础时限 + 当周 planB项目时长`。基础时限默认 **10h**；DOTA2 台账当周「本周时限」有人工值时把它当作**基础时限**，`--cap-hours` 可再覆盖。Plan B 从 `/Users/aaron/workspace/个人/生活/工作时长.md` 的「周汇总」按同一自然周读取。每做 1 小时 Plan B，就给当周增加 1 小时 DOTA 有效额度；这是为了让投入 Plan B 立即得到正反馈。
> **2026-08-17 前沿用旧口径**：不加 Plan B，默认时限 15h。`--days N` 也不对应单个自然周，因此不加 Plan B，维持默认 15h、结余 0。
> **状态 emoji 只由「有效时限+期初结余」红线阶梯决定**：消耗 ≤ 有效时限 → 一律 ✅；超有效时限但仍在结余内 = 💰 合法动用结余；`超限红线 = 有效时限 + 期初结余`，超红线 ⛔、超红线 2h+ 🚨、超红线 5h+ 🛑 下周强制停玩。推荐下限 `有效时限×8/15`、推荐基准 `有效时限×10/15` 只作接近程度提示，不改变 emoji。
> **周末结余公式**：`本周总结余 = 期初结余 + 基础时限 + 当周 Plan B − DOTA 真实消耗`。每次都报基础时限、Plan B 奖励、有效时限、超限红线和按当前数据预计的周末总结余；数字以脚本动态输出为准。

**③ 天梯进度（目标 5000 分）**
> 报当前段位 + 本窗口天梯胜负，按"净胜场 × 每局约 ±25"估算本窗口**上下分**，并算距 5000 还差多少。
> （Valve 已隐藏精确 MMR，OpenDota 给不到具体分；想精确就用 `--mmr 你的真实分`。）

默认账号 **137084212（伯爵红茶）**。**默认窗口 = 当前自然周**（本周一 00:00 → 现在，含今天）；给了天数则按**过去 N 天（截止昨天 24:00，不含今天）**。

> 全部是确定性计算（窗口、求和、预算评判、上下分估算）由脚本完成；你只需跑脚本、把结果讲清楚。


  - **按天 / 按模式** 明细 + 一段 `signals` JSON（含 budget / ladder 结构）。
- 脚本很快（两次 API 调用：对局 + 段位），无需后台。

## 口径说明（讲清楚，避免歧义）

- **真实消耗 = 对局 + 选人 + 匹配/赛后**：纯对局 `duration` 不含选英雄、排队、赛后结算等局外时间，所以会**低估**实际投入；本 skill 用"选人 90s/局 + 额外 180s/局"把这部分补上，得到更接近真实的总时间。这两个是**估算常数**（非逐局精确值），可调。
  - 选人 90s 依据：天梯 Ranked All Pick 草选为 策略 5s + 选人 3 轮 70s ≈ 75s，含禁用阶段/读条取 90s。
  - 额外 180s 依据：用户设定，覆盖匹配排队 + 赛后结算/复盘等不好精确统计的时间。
  - `pre_game_duration`（局前策略时间）字段在 OpenDota 未解析对局上为空、不可靠，故选人时间用固定估算而非该字段。
- **算的是"开局时间在窗口内"的局**：一局只要在窗口内开始，就把它**整局**计入（即便它跨过了午夜）。
- **窗口按本地时区**：服务器返回的是 UTC 时间戳，脚本已转成本地时区再分日，跨时区不会算错。

### 健康预算口径
- **基础时限优先级**：`--cap-hours` > DOTA2 台账当周「本周时限」> 日期默认值。默认值在 2026-08-17 前为 15h，从 2026-08-17 这一周起为 **10h**。`--cap-hours` 覆盖的是基础时限，不是加完 Plan B 的最终值。
- **Plan B 奖励优先级**（只在生效后的自然周）：`--planb-hours` > `工作时长.md`「周汇总」同周 `planB项目时长` > 0。工作台账路径可用 `--work-ledger` 改。周键或时长不可解析时，脚本给 `planb_bonus_source=missing` 并明确警告。
- **有效时限 = 基础时限 + Plan B 奖励**；**超限红线 = 有效时限 + 期初结余**。期初结余优先级：`--balance-hours` > DOTA2 台账中当前周之前最近一个已结算「当前结余量」（支持 `-XhYm` 负债）> 0。
- **预计周末总结余 = 期初结余 + 有效时限 − 当前 DOTA 真实消耗**。当前周尚未结束时它是动态预测：后续 Plan B 会增加它，后续 DOTA 会减少它。
- 推荐下限/基准档位随**有效时限**按比例缩放（推荐下限 = cap×8/15、基准 = cap×10/15），只用于 ✅ 状态里的接近程度措辞。状态 emoji 唯一由动态红线决定：≤有效时限 ✅ / 有效时限~红线 💰 / 超红线 ⛔ / 超红线 2h+ 🚨 / 超红线 5h+ 🛑。
- `--days N` 模式不读台账（不对应某一个自然周），时限用默认 15h、结余按 0。
- 默认自然周窗口**含今天到现在**，这样"本周还能玩多久"是实时的（这点与 `--days` 模式"不含今天"不同，刻意为之——预算要实时）。
- `signals.budget` 重点字段：`base_cap_hours` / `base_cap_source`、`planb_bonus_seconds` / `planb_bonus_human` / `planb_bonus_source`、`effective_cap_hours`、`balance_seconds`、`hard_cap_hours`、`projected_end_balance_seconds`、`remaining_to_cap_seconds`、`remaining_to_hard_cap_seconds`、`over_limit_using_balance`、`over_hard_cap`、`over_hard_severe`、`forced_stop_next_week`。兼容字段 `cap_hours` / `cap_h` 表示**有效时限**，不要把它误说成基础时限。

### 天梯进度口径
- 目标默认 **5000 分**。**OpenDota 拿不到精确 MMR**（Valve 已隐藏，`mmr_estimate` 等多为 null），只拿得到段位 `rank_tier`（如 54 = 传奇4）。
- 因此"当前分数"是**按段位粗估**（每大段≈770、每星≈154）；"本窗口上下分"按**天梯胜负净场 × 每局约 ±25** 估算。两者都标注为估算。
- 用户报了自己的真实分（`--mmr`）→ 用真实分精确算距 5000 的差，并给"本窗口后约 X 分"的预测。

## 示例

**Input:** `/dota2-playtime`（不带天数 → 当前自然周）
**Output:** 若当前周为 `2026-08-17 ~ 2026-08-23`、工作台账 Plan B 为 `4h18m`，则先报："基础时限 10h + Plan B 4h18m = 当周有效时限 14h18m"，再结合期初结余和 DOTA 真实消耗报告红线、剩余额度与预计周末总结余；随后报告天梯和按天明细。

**Input:** `/dota2-playtime 7`
**Output:** 过去 7 天（不含今天）不使用 Plan B 或周结余，维持 15h 比较口径；如实按脚本给出的动态状态回复，但不归档到自然周台账。

**Input:** `/dota2-playtime --mmr 3900`
**Output:** 用真实分 3900 精确算：距 5000 还差 1100；本周净 +2 场 → 估算到约 3950，距目标约 1050。

**Input:** `/dota2-playtime 7 --pick-seconds 75 --overhead-seconds 300`
**Output:** 选人按 75s/局、每局额外按 5 分钟重算真实消耗。
