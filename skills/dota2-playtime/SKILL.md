# Dota2 真实消耗 + 健康预算 + 天梯进度（dota2-playtime）

三件事一次给齐：① 玩 Dota2 的**真实消耗时间**，② 对照**周时长预算**的健康评判，③ **天梯上分进度**。

**① 真实消耗时间 = Σ每局（对局时长 duration + 选人时间 + 匹配/赛后等额外开销）**
> - **对局时长**：OpenDota 每局 `duration` 相加（游戏内 0:00 到结束）。
> - **选人时间**：每局固定 **默认 90 秒**（天梯 All Pick 草选；`--pick-seconds` 可调）。
> - **匹配/赛后等**：每局固定 **默认 180 秒**（排队 + 赛后结算/复盘等不好精确统计的时间；`--overhead-seconds` 可调）。

**② 健康时长预算（按自然周、针对真实消耗时间）**
> **本周时限（cap）动态**：默认 15h，但**若台账当周那行「本周时限」有自设值（如 18h/20h/25h/10h），优先按自设值**；`--cap-hours` 可覆盖。
> **状态 emoji 只由「时限+结余」红线阶梯决定**：**消耗 ≤ 本周时限 → 一律 ✅**（推荐下限 cap×8/15、基准 cap×10/15 只作『接近程度』提示文字，**不触发任何警告 emoji**）；超时限但在结余内 = 💰 合法动用结余；**超限红线 = 本周时限 + 可用结余**（结余自动读台账「当前结余量」列，可为负=负债，`--balance-hours` 可覆盖），**超红线 ⛔ 透支、超红线+2h 🚨 强烈警告、超红线+5h 🛑 下周强制停玩**（停玩周时限照常入结余）。**注意：🚨=超红线≥2h，绝不是"超12h"——时限内再高也是 ✅。**
> 每次都报"距推荐基准/本周时限/超限红线各还剩多少"和当前结余——**数字以脚本动态输出为准，别套死 10/15**。

**③ 天梯进度（目标 5000 分）**
> 报当前段位 + 本窗口天梯胜负，按"净胜场 × 每局约 ±25"估算本窗口**上下分**，并算距 5000 还差多少。
> （Valve 已隐藏精确 MMR，OpenDota 给不到具体分；想精确就用 `--mmr 你的真实分`。）

默认账号 **137084212（伯爵红茶）**。**默认窗口 = 当前自然周**（本周一 00:00 → 现在，含今天）；给了天数则按**过去 N 天（截止昨天 24:00，不含今天）**。

> 全部是确定性计算（窗口、求和、预算评判、上下分估算）由脚本完成；你只需跑脚本、把结果讲清楚。

## 输入

| 参数 | 说明 | 默认 |
|---|---|---|
| 天数（可选） | 给了就按**过去 N 天**（截止昨天 24:00，不含今天）；**不给则按当前自然周** | **自然周** |
| account（可选） | 账号 Steam32 ID | **137084212** |
| `--pick-seconds` | 每局**选人时间**（秒） | **90** |
| `--overhead-seconds` | 每局**匹配/赛后等额外开销**（秒） | **180** |
| `--mmr` | 你的**当前真实天梯分**（手填则精确算距 5000 的差与窗口后预测） | 段位粗估 |
| `--target-mmr` | 天梯目标分 | **5000** |
| `--mmr-per-game` | 每局天梯胜负约 ±多少分（估算上下分用） | **25** |

窗口口径：
- **不给天数** → **当前自然周**：`window_start = 本周一 00:00`，`window_end = 现在`（**含今天**，因为预算要实时反映本周已玩多少）。
- **给天数 N** → `window_end = 今天 00:00`（= 昨天 24:00），`window_start = 今天 00:00 − N 天`（不含今天）。
- 均按**本机本地时区**算。

若用户给了不同的选人/额外时间、或报了自己的真实分，就传对应参数；没说就用默认。

## 口径说明（讲清楚，避免歧义）

- **真实消耗 = 对局 + 选人 + 匹配/赛后**：纯对局 `duration` 不含选英雄、排队、赛后结算等局外时间，所以会**低估**实际投入；本 skill 用"选人 90s/局 + 额外 180s/局"把这部分补上，得到更接近真实的总时间。这两个是**估算常数**（非逐局精确值），可调。
  - 选人 90s 依据：天梯 Ranked All Pick 草选为 策略 5s + 选人 3 轮 70s ≈ 75s，含禁用阶段/读条取 90s。
  - 额外 180s 依据：用户设定，覆盖匹配排队 + 赛后结算/复盘等不好精确统计的时间。
  - `pre_game_duration`（局前策略时间）字段在 OpenDota 未解析对局上为空、不可靠，故选人时间用固定估算而非该字段。
- **算的是"开局时间在窗口内"的局**：一局只要在窗口内开始，就把它**整局**计入（即便它跨过了午夜）。
- **窗口按本地时区**：服务器返回的是 UTC 时间戳，脚本已转成本地时区再分日，跨时区不会算错。

### 健康预算口径
- **本周时限（cap）动态确定，优先级：`--cap-hours` > 台账当周自设「本周时限」> 默认 15h。** 自然周默认模式下，脚本会**自动读取台账**（`/Users/aaron/workspace/个人/生活/DOTA2时长.md`）里**当周那一行的「本周时限」列**；有自设就用自设（如 18h/20h/25h），没有该行就用默认 15h。`--ledger` 可改台账路径，`--cap-hours H` 可强制覆盖。
- **超限红线 = 本周时限 + 可用结余**。可用结余优先级：`--balance-hours` > 台账「当前结余量」列（取当周之前最近一个已结算行，自然周模式自动读，**支持负值** `-XhYm` = 负债）> 0。消耗在「时限 ~ 红线」之间 = **合法动用结余**（脚本报 💰 档）；超红线进入**透支惩罚阶梯**：⛔ 超出计负结余 → 超 2h 🚨 强烈警告 → 超 5h 🛑 下周强制停玩（`signals.budget.forced_stop_next_week`）。
- **推荐下限/基准档位随本周时限 cap 按比例缩放**（推荐下限 = cap×8/15、基准 = cap×10/15；例 cap=15h → 8/10，cap=25h → 13.3/16.7，cap=10h → 5.3/6.7）——但这几档**只用于 ✅ 状态里的『接近程度』措辞（超基准/距时限还剩多少），不产生 ⚠️/🚨 emoji**。**状态 emoji 唯一由「时限+结余」红线阶梯决定**：≤时限 ✅ / 时限~红线 💰 / 超红线 ⛔ / 超红线+2h 🚨 / 超红线+5h 🛑。**旧的"严重 >12h→🚨"已废弃**——时限内消耗再高也是 ✅，🚨 只保留给"超红线≥2h"。
- `--days N` 模式不读台账（不对应某一个自然周），时限用默认 15h、结余按 0。
- 默认自然周窗口**含今天到现在**，这样"本周还能玩多久"是实时的（这点与 `--days` 模式"不含今天"不同，刻意为之——预算要实时）。
- `signals.budget` 里给出 `cap_hours`/`cap_source`（default/ledger/arg）/`balance_seconds`/`balance_human`/`balance_source`（none/ledger/arg）/`hard_cap_hours`（= 时限+结余）/`rec_base_h`/`severe_h`/`remaining_to_base_seconds`/`remaining_to_cap_seconds`/`remaining_to_hard_cap_seconds`/`over_limit_using_balance`（动用结余中）/`over_hard_cap`（超红线，透支）/`over_hard_severe`（超红线 2h+）/`forced_stop_next_week`（超红线 5h+，下周强制停玩；`over_cap_force_stop` 为其兼容别名）等，讲的时候以脚本输出的动态档位为准，别再套死 10/15。

### 天梯进度口径
- 目标默认 **5000 分**。**OpenDota 拿不到精确 MMR**（Valve 已隐藏，`mmr_estimate` 等多为 null），只拿得到段位 `rank_tier`（如 54 = 传奇4）。
- 因此"当前分数"是**按段位粗估**（每大段≈770、每星≈154）；"本窗口上下分"按**天梯胜负净场 × 每局约 ±25** 估算。两者都标注为估算。
- 用户报了自己的真实分（`--mmr`）→ 用真实分精确算距 5000 的差，并给"本窗口后约 X 分"的预测。
