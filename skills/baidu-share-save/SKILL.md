# 百度网盘分享链接 → 逐个转存到我的网盘

把一段文本里的**所有百度网盘分享链接**，像手动操作一样**一条一条**地转存到用户网盘的**指定目录**。

整条链路：**启动隔离浏览器 + 用户登录 + 确认目标路径 → 从文本抽链接(links.json) → 逐条转存(提取码→设路径→保存→API 核实) → 进度落盘可续跑**。

> 本质是串行任务：一个浏览器、一个网盘、有风控，所以是顺序循环，**不要并行化**。
> 与 `pantools-baidu-transfer` 的区别：那个是从 PanTools 目录页逐个点分享；本 skill 的输入是现成的百度分享链接文本。保存页的选择器沿用那边 2026-06 实测通过的版本。

---

## 触发约束（硬约束）

**只在用户显式调用时触发**：`/baidu-share-save ...`、"用/调用 baidu-share-save ..."。用户只是贴了链接、随口说"帮我存一下"不算。

## 参数

- **目标网盘路径**（必填）：如 `/资料/课程`，`我的网盘/资料/课程`、`全部文件 > 资料 > 课程` 也行，多级可以。没给就先问用户，不要猜。
- **文本**：一个文本文件路径（txt/md 等），或者用户直接粘贴在对话里的内容。
- 需要 `node`（v18+）和系统 Chrome。`scripts/` 首次使用前要 `npm i`（只装 `playwright-core`，不下载浏览器）。

## 工作目录

默认 `~/workspace/aiDownload/baidu-share-save/`（可用环境变量 `BAIDU_SAVE_WORK` 改）：
- `chrome-userdata/`：隔离浏览器的 profile，百度登录态持久化在这里，下次不用重新登录；
- `runs/<YYYYMMDD-HHMMSS>/`：每一批一个目录，里面放 `input.txt`、`links.json`、`progress.json`、`run.log`。

下文 `S` 指本 skill 目录下的 `scripts/`，`RUN` 指本批的 run 目录。

## 步骤

### 1. 启动隔离浏览器 → 用户登录 → 确认保存路径

```bash
[ -d "$S/node_modules/playwright-core" ] || (cd "$S" && npm i)
bash "$S/launch.sh"          # 输出 STARTED/REUSE http://127.0.0.1:<port>；已在跑就复用
node "$S/check.js" "<目标网盘路径>"
```

`check.js` 退出码：
- `0` 已登录且目标目录存在：进入第 2 步。
- `2` 未登录：告诉用户「请在弹出的独立 Chrome 窗口里登录百度网盘（扫码/账号）」，等用户说好了再跑一次 `check.js`。
- `3` 目标目录不存在：请用户在该窗口里新建这个目录，或者换一个路径，然后再跑一次。不带参数跑 `check.js` 会列出网盘根目录，可以帮用户挑路径。

**目标路径确认存在之前，不进入第 3 步。**

### 2. 从文本里抽取分享链接

用户粘贴的文本要**原样**写进 `RUN/input.txt`，不要改写、删减或手工挑链接。给的是文件路径就直接用。

```bash
node "$S/extract.js" "$RUN/input.txt" "$RUN/links.json"
```

脚本支持：
- `/s/1xxx`、`share/init?surl=xxx` 和 `yun.baidu.com` 三种链接写法；
- 提取码在 URL 的 `?pwd=` 里，或写在链接后面、下一行，或同一行链接前面（`提取码/密码/访问码/pwd/code`）；
- 同一链接出现多次时去重。

抽完后给用户报：
- **总条数**；
- 每条的标题、链接 key 和提取码；
- **没找到提取码的条目**（可能本来就是公开分享，照样会尝试保存）；
- `SHORTLINK-FAILED`：没能解析成百度链接的第三方短链，以及失败原因。
- `SUSPECTS`：文本里提到 baidu 网盘但没解析成链接的片段。原样列给用户，**不要自己猜着补全链接**。

**第三方短链**（如 `v.v8l.cn/s/…`，链接后面跟着提取码、但域名不是百度）：
- 这类短链在桌面端只显示"仅允许手机端访问"的扫码页，对手机 UA 则会 302 跳到真正的 `pan.baidu.com/s/…?pwd=`。
- `extract.js` 会先用手机 UA 逐个跟随跳转，把短链替换成百度直链，再抽取。这是用户在 2026-11-10 明确授权的做法。
- 解析出来的条目带 `via` 字段，记着原始短链。
- 解析失败的列在 `SHORTLINK-FAILED` 里报给用户，不要猜。

然后直接进入第 3 步。用户调用本 skill 就是要全部保存，不必再确认。

### 3. 逐条转存到目标目录

```bash
node "$S/save-all.js" "$RUN/links.json" "$RUN/progress.json" "<目标网盘路径>" 2>&1 | tee -a "$RUN/run.log"
```

- 每条大约 15–25 秒。**超过 5 条就后台运行**，并持续盯 `run.log`。
- 后台运行时，用 Monitor 对 `run.log` 做 `tail -F`，并用 grep 过滤，只看这几类行：
  - `WAIT-USER`、`PICK-FAIL`、`RECONNECT`、`STOP`、`DONE`；
  - 非 `saved` 的状态；
  - 第 2 档及以上的 `RATELIMIT`；
  - 每 25 条的进度。

  Monitor 每 30 分钟会过期，过期后要重新挂上。不要每条都通知。
  Monitor 的通知可能晚到（2026-11-12 实测，WAIT-USER 等到脚本退出才送达），所以**第 1 条要在前台盯**：后台启动后，用前台的 `until grep` 循环等 `[1/N]`、`WAIT-USER` 或 `STOP` 出现，第一条通常就是要选路径的那条。
- 日志里出现 `RATELIMIT` 行时，说明碰到"请求超时/请稍后/频繁"这类暂时限流。脚本会自己退避重试，依次等 1、2、4、8、10 分钟，不用管。连续 5 次都失败才会停下。
- 日志里出现 `RECONNECT` 行时，说明 CDP 连接断了（常见原因是电脑休眠）。脚本会自己重连，连续 3 次都失败才停下。跑长批次前，建议用户关掉自动休眠，或者运行 `caffeinate -i`。
- 日志里出现 `WAIT-USER ...` 行时，说明脚本在等用户操作（最多等 15 分钟），要**立刻把这句话转告用户**：
  - **路径没选上**：按 WAIT-USER 里写的布局转告。底部栏布局：点「最近保存路径」旁边的图标，选中目标目录后点「确定」；顶部按钮布局：点右上角「保存到网盘」，选中目标目录后点「确定」。两种弹窗点确定都直接保存，不用再点保存按钮。脚本检测到路径正确，或者目标目录里出现新文件后，会自动继续。
  - WAIT-USER 前面的 `PICK-FAIL <原因>` 说明自动选路径卡在哪一步（选择框没弹出、目录树里找不到某级、被提示层挡住、最后一级没选中），排查时先看它。
  - **安全验证**：只有出现真正的验证码/滑块时才会这样。请用户在浏览器里完成验证。
- 中断了用同样的命令重跑即可，已经 `saved`/`exists`/`dead` 的条目会自动跳过。

单条流程：
1. 新标签打开分享链接（URL 里带 pwd）。
2. 如果停在提取码页：空的就填上提取码，点「提取文件」。
3. 判断布局（同一链接会随机出现两种）：出现底部的 `.save-path` 就是**底部栏布局**；等了约 5 秒仍没有、但有可见的右上角 `a[node-type=shareSave]`，就是**顶部按钮布局**。
4. 用网盘 API 列一次目标目录，记下保存前的状态。然后读分享页的 `window.locals.get('file_list')`（每项的 `server_filename`，两种布局都有）：分享里的每一项在目标目录都已有**完全同名**的，就记为 `exists`、不转存。百度遇到重名会加后缀再存一份，所以必须在这里拦住。只有部分同名时照常转存。
   - **顶部按钮布局**：在页面内点右上角「保存到网盘」，弹出旧版 `.dialog-fileTreeDialog`（每次都要选目录，底部有「最近保存路径」文字）。按第 5 步的树选择选中目标目录，确认选中后点 `a.g-button-blue-large`（确定）即转存，然后直接跳到第 7 步。
5. 底部栏布局下，如果 `.save-path`（「最近保存路径」）不等于 `我的网盘/<目标>`：
   - 在页面内点 `.bottom-save-path-icon`，打开 `.share-save-dialog` 选择框。
   - 关掉"转存到同步空间"的引导提示，在 `.treeview-txt` 里逐级点目录。
   - 核对最后一级是 `.treeview-node-on`（选中状态），再点 footer 的 `button.wp-base-button--primary`（确定）。
   - **新版点确定就直接转存了**，所以接着先查目标目录：已经多出文件就算成功，不再点保存，防止重复。
   - 自动选择失败会重开选择框再试 1 次，两次都不行才 `WAIT-USER`。某一级目录找不到时，会先把上一级折叠再展开一次，应对刚新建的目录还没出现在列表里。
6. 路径本来就对（第二条起通常如此）：在页面内 click `button.bottom_save_btn`（「保存到网盘」）。
7. 读保存后**新出现**的提示文字。
8. 再列一次目标目录，**多出来的文件名才算真的存进去了**。
9. 关闭标签，随机等 6–12 秒，处理下一条。

`progress.json` 里每条的状态：

| status | 含义 | 重跑时 |
|---|---|---|
| `saved` | 目标目录里确实多出了文件（`added` 字段记着文件名） | 跳过 |
| `exists` | 保存前发现目标目录已有完全同名的（note 写「目标目录已有同名，未转存」），或者百度提示已存在/已保存过 | 跳过 |
| `dead` | 链接失效、被取消、过期或违规 | 跳过 |
| `badcode` / `needcode` | 提取码错误 / 需要提取码但文本里没有 | 请用户补提取码后重跑 |
| `limit` | 超过单次转存的文件数上限（非会员较低） | 报给用户 |
| `unverified` | 点了保存，但目标目录没见到新文件 | 重跑前先用 `listDir` 确认目录里确实没有，再重跑（防止重复保存） |
| `nofilepage` / `error` | 页面没加载出保存栏，或者抛了异常（脚本已自动重试 1 次） | 可以重跑；还不行就用 `shot.js` 截图排查 |

致命状态会让整批停下：
- `pathfail`：退出码 3；
- `blocked`（验证超时）/ `ratelimited`（连续限流 5 次）：退出码 4；
- `quota`（网盘空间不足）：退出码 5；
- `disconnected`（重连 3 次都失败）：退出码 6。

用同样的命令重跑，就会从停下的那条接着处理。

### 4. 收尾汇报

读 `progress.json` 的 `stats`，按状态汇总报给用户：
- 成功几条，每条存进去的文件名；
- 失败的条目逐条列出：标题、链接、原因；
- 能处理的给出下一步，比如补提取码后重跑、去网盘核对 `unverified`。

浏览器窗口保留不关，登录态留着下次用。

## scripts/

- `lib.js`：通过 `chrome-userdata/DevToolsActivePort` 连接 CDP，`listDir` 网盘 API，`normPath` 路径归一化。
- `launch.sh`：启动或复用隔离 Chrome，调试端口自动分配。
- `check.js [目标路径]`：检查登录态和目标目录。
- `extract.js <input> <links.json>`：先解析第三方短链，再从文本里抽链接。也导出 `extractLinks(text)` 和 `resolveShortLinks(text)`。
- `save-all.js <links.json> <progress.json> <目标路径>`：逐条转存，可断点续跑。
- `shot.js [url片段] [out.png]`：给某个标签截图，排查页面状态用。

## 坑位备忘

- **路径不对绝不点保存**：百度会记住上次的保存目录，第二条起通常不用再选。但第一条（或者用户中途在别处存过东西之后）必须核对 `.save-path`。自动选不上就进入 `WAIT-USER` 等用户手选，超时就停下整批，不往错误的目录里存。
- **成功与否以 API 为准**：UI 提示可能缺失或误报，统一用 `/api/list?dir=<目标>` 对比保存前后。所以也别手动往目标目录里同时放别的东西，否则会干扰对比。
- **隔离浏览器**：用独立的 user-data-dir 避开 profile 锁；端口用 `--remote-debugging-port=0` 让 Chrome 自己挑，不会和用户 Chrome 的 9222 冲突。
- **绝不关用户的 Chrome**：脚本里不调用 `browser.close()`，用 `process.exit()` 断开连接。只在用户要求时，用 `pkill -f "baidu-share-save/chrome-userdata"` 清理本 skill 自己起的实例。
- **2026-11 百度改版（实测）**：
  - 「保存到网盘」从 `a.bottom_save_btn` 改成了 `button.bottom_save_btn`。
  - 选路径弹窗换成了 `.wp-modal__panel.share-save-dialog`，确定/取消在 `.wp-modal__footer` 里，是 `button.wp-base-button`。
  - 弹窗里点确定就会直接转存。
  - 旧选择器（`.dialog-fileTreeDialog`、`a[node-type="bottomShareSave"]`）留作兜底。
  - 以后百度再改版，症状会是 `unverified` 或 `WAIT-USER` 突然变多，先用只读 evaluate 查按钮的 DOM 链路。
- **两种页面布局随机出现（2026-11-12 实测）**：大多数时候是底部栏布局；偶尔是没有底部栏、只有右上角「保存到网盘」的顶部按钮布局，点开是旧版 `.dialog-fileTreeDialog`。它的 `.treeview-txt` 带 `node-path="/a/b"`，确定/取消是 `a.g-button`。顶部布局下「确定」之后的完整保存流程，以及它的选中 class 是否也是 `.treeview-node-on`，都还没实测过。选中状态核对不通过时脚本不会点确定，会转成 WAIT-USER，所以不会存错目录。
- **第一条选路径曾失败一次（2026-11-12）**：底部栏布局，`pickInTree` 返回失败，原因当时没留日志（现在会打印 PICK-FAIL）。事后逐步重放每一步都正常。可能原因有两个：目标目录 20261112 刚新建、目录树没列出来；或者引导提示层晚出现挡住了点击。这两种情况现在都有处理。
- **「保存到网盘」可能被 canvas 遮挡**：要用页面内的 `el.click()`。
- **百度风控（2026-11 实测，378 条）**：
  - 每条间隔 6–12 秒时，大约每 40 条出现一次"请求超时，请稍后再试"，退避 1 分钟就能恢复，全程没有出现验证码。
  - "请求超时"不是验证码，以前把它当成需要人工验证，导致整批停了下来。
  - 有时提示的是"文件转存中… 请求超时"，文件可能在退避期间才转存完。所以重试前要先和第一次尝试前拍的目录快照对比。快照读取失败时绝不能当成空集合，否则整个目录都会被误判为新保存的文件。
- **长批次会碰到电脑休眠**：休眠后 CDP 断开，旧版脚本会把剩下的每一条都快速标成 `error`。现在会先 `RECONNECT`。
- **未实测的假设**：
  - 多文件分享不勾选时，「保存到网盘」会保存全部内容（单个文件夹的分享已实测能整体存进去）。
  
  多级目录的树选择（`li > ul` 逐级找）已在 2026-11-12 用两级目录实测通过。如果出现 `unverified`、`pathfail` 或 `nofilepage`，先用 `shot.js` 截图看页面实际结构，再改选择器，并把结论更新到这里。
