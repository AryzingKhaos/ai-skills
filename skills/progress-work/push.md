# push · 推送到远端

用户输入的 git 子命令里有 `push`。先按 SKILL.md「git 子命令的公共规则」完成检查（带 `--fetch`）和确认，再对每个项目执行下面的步骤。

## 步骤

1. **能否推送**：
   - 没有上游分支 → 阻塞，问用户推到哪里，不自己 `--set-upstream`；
   - 其它阻塞（detached HEAD、未完成的 rebase 等）→ 跳过，写明原因。
2. **有没有东西可推**：领先上游 0 个提交、本次也没有新提交 → "没有要推送的提交，跳过"。
3. **身份**：未推送的提交里有作者或提交者不是 `Aaron <aaron4lawliet@gmail.com>` 的，必须是检查阶段已经列出、用户同意推送的，才往下走。本次 commit 刚产生的提交也要看一眼作者。
4. **推送**：执行 `git push`，推到当前分支的上游。
5. **被拒**（落后上游、保护分支、权限等）→ 如实汇报错误，**不 pull、不 rebase、不 `--force`**，问用户怎么处理。
6. **汇报**：推送到哪个远端分支、推了几个提交。本次 commit 成功但 push 失败时，必须明说"提交已完成、推送未完成"。

## 示例

| 输入 | 处理 |
|---|---|
| `/progress-work push` | 只推送每个项目已有的未推送提交，不写文案、不提交 |
| `/progress-work draft commit push` | 每个项目：写文案 → 提交 → 推送 |
| `/progress-work push roleflow` | 只推送 roleflow |
