# progress-work · 项目每日进度

## 铁律

1. **只能显式调用。** 必须是用户亲手输入 `/progress-work`。对话里提到做了什么，都不触发。
2. **不猜测。** 用户没明确说的内容不写进文件，包括：
   - 项目：更新信息对应不到**唯一**一列时，不要选"最像的那个"，列出现有项目问用户是哪一个，或者是否新增项目。
   - 日期：用户没提日期就是今天。说了"昨天""前天""9 月 12 号"这类能确定的日期就换算；"前几天""上周"这种说不准是哪天的，先问。
   - 内容：只写用户说的事，可以精简措辞，不补充用户没说的细节。
3. **每次都重新读文件**，不依赖对话里之前读到的内容，用户经常手动改。

### 项目开发细则

- 每个项目一个 `### 项目名` 小节，里面的内容**由用户手写，skill 只读不改**。
- 唯一会动这里的情况是新增 / 删除项目，见下文。

### 项目记录

- 每个月一个 `### YYYY-MM` 小节，放在 `## 项目记录` 下面，**新的月份放在上面**；月内日期从 1 号到月底升序排列，每天一行，没有记录的格子留空。
- 日期列格式固定为 `YYYY-MM-DD 周X`，全文唯一，Edit 时用它定位行。
- **一格里一条进度占一行。** Markdown 表格的一行不能真的换行，所以多条进度之间用 `<br>` 分隔（Typora、Obsidian、VS Code 预览、GitHub 都会渲染成换行）。格子已有内容时，新内容接在最后一条后面：`旧内容<br>新内容`，不覆盖旧内容。
- 用户一次说了同一项目的好几件事，拆成多条，各占一行，用 `<br>` 连接。
- 格子里不能出现 `|` 和真正的换行：`|` 改写成 `/`。
- 顶部的 `更新时间` 每次写入都要刷新，用 `date '+%Y-%m-%d %H:%M'` 获取当前时间。
- 用户手动改过格式时，按实际格式读取，写入时尽量保持原样，不强制改回模板。

### 新建月份表

要写入的日期所在月份还没有表时，先建表再写：

- 列沿用**最近一个月**表格的全部项目，顺序不变；
- 行从 1 号到当月最后一天，星期几用脚本算，不要心算：

  ```bash
  python3 -c "import calendar,datetime as d;y,m=2026,10;print('\n'.join(f'| {d.date(y,m,i).isoformat()} 周{\"一二三四五六日\"[d.date(y,m,i).weekday()]} |'+'  |'*3 for i in range(1,calendar.monthrange(y,m)[1]+1)))"
  ```

  其中 `y,m` 换成目标年月，`*3` 换成项目数；
- 新表以 `### YYYY-MM` 为标题，插在 `## 项目记录` 下第一个月份小节之前，保证新月份在上面。

## 用法一：`/progress-work`（不带参数）→ 展示

只读文件，不写入。

1. 读取数据文件，找到**当前月份**的表。本月还没有表或整张表都是空的，就说明"本月还没有记录"，并给一个更新写法的示例，到此结束。
2. 输出本月表格，**只保留有内容的日期行**（空行不展示），列保持原样。终端里 `<br>` 不会换行，展示时把它换成 `；`。
3. 表格下面列出每个项目最近一次有记录的日期和内容。某个项目本月一条记录都没有，就往上个月找；上个月也没有，写"近两个月无记录"。
4. 不评价做得多少，不给安排建议。

## 用法二：`/progress-work <更新信息>` → 更新

1. **读文件**，拿到最近一个月表格的项目列名。
2. **确定项目**：
   - 更新信息里出现了某个列名（不区分大小写），或者是完全无歧义的简称（只命中一列）→ 就是它。
   - 命中多列，或者一列都对不上 → 停下，列出现有项目问用户。**不要自己选。**
   - 一条信息可以同时写多个项目，每个项目分别按上面的规则确定。
3. **确定日期**：按铁律第 2 条换算；该月没有表就按「新建月份表」先建。
4. **写入**（用 Edit 做精确替换，不整体重写文件）：
   - 用 `| YYYY-MM-DD 周X |` 定位行，把内容写进对应列的格子，已有内容用 `<br>` 追加；
   - 刷新顶部更新时间。
5. **回显**：说明写到了哪天、哪个项目，并把格子现在的内容逐条列出（一条一行）。

### 新增 / 删除项目

- 用户明确说"新增项目 XXX"：
  - 给**当前月份**的表加一列，放在最右边，本月所有格子留空；以前月份的表不动。之后新建的月份表会自动带上这一列。
  - 在 `## 项目开发细则` 最后加一个空的 `### XXX` 小节。
- 用户明确说"删除项目 XXX"：
  - 只从**当前月份**的表删这一列，删之前确认该列本月没有内容；有内容就把内容列给用户，问清楚再删。以前月份的表不动。
  - `## 项目开发细则` 里的 `### XXX` 小节：为空就一起删；有内容就问用户要不要删。

### 示例

| 用户输入 | 处理 |
|---|---|
| `/progress-work roleflow 写完 v2 的 switch 子命令` | 今天那一行，roleflow 格子写入"写完 v2 的 switch 子命令" |
| `/progress-work ai-skills 修了 work-time 的测试，顺便给 rest-check 加了配额查询` | 两件事拆成两条：`修复 work-time 测试<br>rest-check 加配额查询` |
| `/progress-work 昨天 llmWikis 整理了 aiagentWiki 索引；ai-skills 加了 progress-work` | 换算成昨天的日期，分别写 llmWikis 和 ai-skills 两个格子 |
| `/progress-work ai-skills 更新 dota2-playtime` | 今天 ai-skills 格子已有内容 → 末尾加 `<br>更新 dota2-playtime` |
| `/progress-work 新增项目 dota2工具` | 当前月份表最右边加一列，项目开发细则末尾加 `### dota2工具` |
| `/progress-work wiki 补了两篇笔记` | "wiki"只命中 llmWikis → 写入；如果同时还有 xxWiki 列，就先问是哪一个 |
| `/progress-work 前几天 roleflow 改了文档` | "前几天"说不准是哪天 → 先问具体日期 |
| `/progress-work 学英语 练了 30 分钟` | 对应不到任何列 → 列出现有项目，问是写进某列还是新增项目 |
