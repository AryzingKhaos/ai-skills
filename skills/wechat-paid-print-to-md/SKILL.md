# 微信付费文章：打印件 + 全选文本 → 图文 Markdown

把一篇微信公众号**付费**文章还原成带本地配图的 Markdown 存档（主要喂进各 wiki 的 `raw/`）。
付费文章只能在微信内置浏览器里看，普通下载器抓不到，所以用户会手工准备两份原料：

- `text.txt`：在文章里**全选复制**得到的纯文本——文案完整，但每张配图只留下一个独立成行的 `图片` 占位、且图本身没复制下来。
- `print.pdf`：把同一篇文章**打印成 PDF**——既是版式参照，**通常也已内嵌全部正文图的原始分辨率版本**（Chromium 打印件特性）。

本 skill 的核心：按 `print.pdf` 的版式，把 `text.txt` 的文案与从 PDF 抽出的正文配图**按出现顺序 1:1 对位**组合成 md。

## 触发方式（必须显式调用）

只有用户**点名本 skill**时才执行，例如：

- `/wechat-paid-print-to-md --text /path/text.txt --pdf /path/print.pdf --out /path/保存目录`
- “用 wechat-paid-print-to-md 把 37 这篇付费文章组合成 md”
- “调用 wechat-paid-print-to-md”

**不要**因为用户贴了 text.txt / print.pdf、或说“帮我把这篇整理成 md”就自动触发——必须有明确的 skill 名称或斜杠命令。

## 参数（三个路径必填，且无默认值）

| 参数 | 必填 | 说明 |
|---|---|---|
| `--text` | ✅ | 全选文本 `text.txt` 的路径 |
| `--pdf`  | ✅ | 打印件 `print.pdf` 的路径 |
| `--out`  | ✅ | md 的**保存母目录**；产物落在 `<out>/<序号>-<标题>/` |
| `--seq` | 否 | 文章序号；缺省取 `text.txt` 父目录名（如 `.../神光课程/37/` → `37`） |
| `--title` | 否 | 标题；缺省取 `text.txt` 第一行（自动去掉“已付费”） |
| `--account`/`--author`/`--date`/`--prev`/`--series` | 否 | 头部元信息；从 `print.pdf` 抬头/页脚读到后传入 |
| `--min-width`/`--min-bytes`/`--expect`/`--force` | 否 | 正文图筛选阈值与映射兜底（见下） |
| `--static-nums "0,1,5"` | 否 | **含视频/装饰图的文章用**：精确指定哪些内嵌图 num 是静态正文图（按出现顺序），绕过尺寸自动筛。见「含视频的文章」 |
| `--heading "Agent 是什么？"` | 否 | 把正文里**与此文本完全相同的整行**提升为 `## 标题`（可多次传）。`总结` 默认自动识别 |
| `--code-lang typescript` | 否 | 代码段默认语言（默认 `typescript`）。脚本会**自动**把纯 shell/.env 段判为 `bash`、JSON 段判为 `json`；其余用本默认值。见「代码围栏」 |
| `--no-fence` | 否 | 关闭自动代码围栏（默认开启） |

> ⚠️ 若用户没给齐 `--text` / `--pdf` / `--out` 三个路径，**停下来向用户索要**，不要自己编默认路径。

## 执行步骤

1. **确认三个必填路径**都由用户给出；缺任何一个就先问用户。

2. **先视觉读 `print.pdf`**（用 Read 工具，按页读完）——这一步是必需的，用来：
   - 拿到**头部元信息**：第 1 页的标题、公众号、作者、发布时间；末页的“上一篇 / 系列 / 修改日期”。
   - 看清**版式与配图**：每张正文图画的是什么、出现在哪段之后、是否有“同一页两张图”的情况，心里建立“第 N 个『图片』占位 ↔ 哪张图”的预期。
   - 认出末尾的**评论区/页脚**（“N 人付费”头像墙、写留言、二维码、图标）——这些不是正文。

3. **运行脚本**（把第 2 步读到的元信息一并传入，一次到位）：

   ```bash
   python3 /Users/aaron/code/ai-skills/skills/wechat-paid-print-to-md/scripts/build_md.py \
     --text "<text.txt>" --pdf "<print.pdf>" --out "<保存母目录>" \
     --seq <序号> --title "<标题>" \
     --account "<公众号>" --author "<作者>" --date "<日期>" \
     --series "<系列>" --prev "<上一篇>"
   ```

   脚本会：抽出 PDF 内嵌图 →（按 `宽≥min-width 且 字节≥min-bytes` 把正文图与头像/图标分开）→ 检查“正文图数 == 文案里『图片』占位数” → 一致就按顺序把图复制成 `images/01..NN`、把每个 `图片` 占位替换成图片引用、并在“留言”处截断评论区 → 写出 md。脚本会打印每张正文图的页码/尺寸、被排除的小图、以及最终结果。

   传 `--heading` 标记标题行（见「标题格式」）。

4. **核对脚本输出**：
   - **计数一致（正常情况）**：对照第 2 步的视觉预期，抽查几处图文是否对位（尤其同页多图的位置）。一致即完成。
   - **计数不一致（`MISMATCH`，退出码 3）**：脚本不会乱建。**最常见原因是文章含视频**（见「含视频的文章」）。其它处理：
     - 误把某正文图当小图排除 / 或反之 → 调 `--min-width`、`--min-bytes`。
     - 确认顺序无误、只是想强行按序构建 → 加 `--expect <正文图数> --force`。
     - 某个占位对应的图在打印件里**是空白**（网页懒加载没渲染出来）→ 进入第 5 步缓存兜底。

5. **微信缓存兜底（仅在打印件缺某张正文图时）**：
   - 先**向用户说明并请求授权**访问微信本地缓存（用户已表示这类访问“全部允许即可”，但仍要显式说明）。
   - 到 `~/Library/Containers/com.tencent.xinWeChat/Data/.../xwechat_files/<wxid>/cache/<年月>/HttpResource/` 下，按图片在文中的**前后顺序/内容**找到缺失的那张，放进 `images/` 对应序号，再修好 md 里的引用。
   - 只取资源图片，不碰 Cookies/History 等会话/凭据文件。

6. **补全与汇报**：若脚本头部留有“（待人工核对）”，用第 2 步读到的信息补全（重跑脚本带 `--flag`，或直接编辑 md 头部）。最后向用户汇报：标题、序号、配图数量、保存路径、以及是否动用了缓存兜底。

## 产物结构

```
<--out>/<序号>-<标题>/
├── <序号>-<标题>.md     正文 Markdown；头部含公众号/作者/日期/系列/上一篇 + 归档说明；
│                         每个「图片」占位按版式换成 ![图N](images/NN.ext)；
│                         标题行为 ## ；视频位置为 📹 注释（见下）
└── images/              正文配图 01.ext .. NN.ext（从 print.pdf 内嵌原图抽取，保留真实格式）；
                         视频首帧（如有）另存 videoN-xxx.jpg
```

## 含视频的文章（重要）

有些文章（尤其演示类教程）会内嵌**演示视频**。视频**无法本地归档**，处理要点：

- **占位差异**：视频在 `text.txt` 里**不占「图片」占位**（只剩“看这个视频：”这类引导句），但在打印件里会留下“视频帧/空白播放框”被一并抽出 → **大图数 ≠ 占位数 → 脚本报 MISMATCH**。这是正常现象、不是 bug。
- **挑出真正的静态正文图**：看脚本打印的“大图清单 + 分类标注”（`[正文图?]`/`[暗截图]`/`[空白框]`），结合视觉读 `print.pdf`，确定哪些 `num` 是真正的静态配图，用 `--static-nums "n1,n2,…"`（按出现顺序）重跑。`[空白框]`=没渲染出画面的视频框、`[暗截图]`=多为视频帧，一般都不是正文图。
- **手工补视频注释**：脚本放好静态图后，在 md 里视频对应位置（“看这个视频：”、以“：”结尾后接视频的句子之后）**手工插入** 📹 注释，格式：
  ```markdown
  > 📹 **视频（约 M:SS）**：<这段视频演示了什么>。（演示视频，无法本地归档）
  >
  > ![视频N首帧·简述](images/videoN-简述.jpg)   ← 打印件捕获到首帧才加这行
  ```
  打印件捕获到首帧的（`[暗截图]`类、非空白），把对应 `img-XXX` 拷进 `images/` 作示意；空白框的只留文字注释。
- 视频时长可从打印件视频框角上的时间戳（如 `01:03`）读到。

## 标题格式

`text.txt` 里的小标题（如 `总结`、`Agent 是什么？`、`Greedy 贪心策略`）会和正文混成普通段落。需要把它们**提升为 `## 标题`**：

- `总结` 脚本**自动**识别。
- 其余标题：视觉读 `print.pdf`，认出被加粗/居中/变色的标题行，用 `--heading "<整行原文>"`（可多次传，文本须与 text.txt 整行完全一致）。
- 拿不准的（如“X：一长串说明”那种加粗行）宁可不提升、留作正文。

## 代码围栏

`text.txt` 里的代码是纯文本（散落在散文之间）。脚本**默认自动**把连续的代码段包成带语言的围栏 ` ```lang `：

- **语言判定**：默认 `typescript`（本系列课程基本都是 TS/JS）；纯 shell/命令行（`pnpm install`、`node x.mjs`、`docker`、`nest` 等）与 `.env` 段判 `bash`；`{ "key": ... }` 形判 `json`；多行 SQL/Cypher（`SELECT/CREATE/MATCH…`）判 `sql`；`key:` 缩进结构判 `yaml`。可用 `--code-lang` 改默认值、`--no-fence` 关闭。
- **识别原理**：以“未缩进的中文散文行”为代码块边界；代码里的中文（注释、字符串值、对象属性 `name: '中文'`、字符串数组元素 `'中文',`）仍算代码。脚本用**反引号模板状态跟踪**，确保多行中文模板字符串（如 `new SystemMessage(\`…中文…\`)`、`const case1 = \`…中文…\``）整段留在代码块内，不被中文行劈开。
- **已知小限制**：微信全选复制偶尔丢失缩进——若 `.env`/`docker-compose.yml` 的键被拍平到行首，可能被判成 `bash`/`typescript` 而非 `ini`/`yaml`（纯高亮层面、不影响内容）；个别 `console.log(` 单独成行结尾是 `(` 的会被误劈，核对时手工合回即可。
- 图片 `![…]`、视频 `> 📹`、`##` 标题等不会被卷进围栏。
- **核对**：跑完抽查几个围栏——语言对不对、有没有把散文误当代码（或反之）、模板字符串有没有被截断。个别误判直接手改 md 即可。

## 说明与边界

- **多数文章不需要缓存**：Chromium 打印件一般把所有正文图按原始分辨率内嵌进了 PDF，脚本直接抽即可；缓存兜底是少数“某图打印空白”时才走。
- **正文图 vs 评论头像的区分**靠尺寸阈值（默认宽≥600 且≥50KB）：公众号正文配图通常 1080px 宽、几百 KB；评论区头像/图标多是 ≤132px、几 KB。遇到正文里有小尺寸示意图被误排，调 `--min-width`/`--min-bytes` 或 `--force`。
- **“正文图数 == 占位数”是关键校验**：相等才能放心按序对位；不等一定要人工视觉核对，别盲信（含视频的文章必然不等，见上）。
- **评论区截断**：脚本遇到独立成行的 `留言` 或 `留言 64`（带评论数）即截断、丢弃其后整段评论。
- 脚本只做“图文组合归档”。之后把成品 `ingest` 进 wiki，按对应仓库 `script/commands/ingest.md` 另行处理。
- 与 `wechat-article-downloader` 区分：那个抓**免费**文章的网页（有链接即可）；本 skill 处理**付费**文章（抓不到网页，只能靠用户手工导出的 text.txt + print.pdf）。
