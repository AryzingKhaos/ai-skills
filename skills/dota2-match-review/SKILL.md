# Dota2 单局数据复盘（dota2-match-review）

对**单独一局** Dota2 做**数据驱动复盘**，默认复盘账号 **137084212（伯爵红茶，传奇段，中单/劣单为主）**。

整条链路：**触发 OpenDota 解析录像 + 拉逐分钟数据（脚本，确定性）→（可选）拉 STRATZ 的 IMP/对线判定/奖章 → 读脚本算出的"数据卡"→ 结合玩家画像写五维判断 → 落地中文复盘报告**。

> 核心价值：**用真实逐分钟数据**回答"我个人到底哪里出了问题"，而不是凭印象。确定性数字（对线@10、经济曲线、死亡时间线、百分位、MVP-proxy；接 STRATZ 后还有 **IMP 表现分/对线胜负判定/奖章**）全部由脚本算；**判断（责任归属/选人是否适配/没拿 MVP 的原因）由你（Claude）基于数据卡 + 下方玩家画像来写。**

---

## 触发约束（硬约束）

**只在用户显式调用时触发**，仅以下两种形态算显式调用：
1. 斜杠命令：`/dota2-match-review <match_id>`
2. 用户消息里明确出现 skill 名 `dota2-match-review`，或明确说"用/调用这个 skill 复盘 <match_id>"

❌ **禁止模糊匹配**：用户只是聊某局、问"这把为什么输/我这把怎么样"而**没点名 skill**，按普通对话处理，不要自动启动。

## 前置依赖

- `python3`（仅用标准库 urllib，无需 pip 安装任何东西）。
- **联网**（访问 `api.opendota.com`；接 STRATZ 时还访问 `api.stratz.com`）。本机若 bash 沙箱拦网络，用 `dangerouslyDisableSandbox`。
- **录像时效**：OpenDota 一般只保留**约最近 1–2 周**的录像可解析。太老的局触发解析也回不来逐分钟数据——脚本会检测并降级（见下）。
- **STRATZ token（可选，强烈推荐）**：接上后能拿 **IMP（每局每人神经网络表现分）、对线胜负判定、奖章(MVP/TOP_CORE/TOP_SUPPORT)、位置识别**——这些 OpenDota **完全没有**，且 STRATZ 预解析所有公开局、**留存比 OpenDota 久**（OpenDota 过期的老局，STRATZ 往往仍有 IMP/对线判定）。token 走环境变量 `STRATZ_TOKEN` 或文件 `~/.stratz_token`（已配置）。**没有 token 也能正常跑**，只是少第 10 节。token 获取：Steam 登录 stratz.com → https://stratz.com/api → My Tokens → 复制 JWT（JWT 约 1 年过期，过期后 403 需重新生成）。

## 执行步骤

### 0. 先把"对局引用"解析成 match_id（参数不是纯数字时）

用户经常**不报编号**，而用自然语言指代，如『最近的那局幽鬼』『倒数第二近的混沌骑士』『最近一场』『上一把宙斯』。**用户不需要记任何参数**，由你来解析：

1. 参数已是**纯数字** → 直接当 match_id，跳到第 1 步。
2. 否则：
   - 把用户说的**中文英雄名映射成英文**（幽鬼→Spectre、混沌骑士→Chaos Knight、宙斯→Zeus、蓝猫→Storm Spirit、痛苦女王/女王→Queen of Pain、电炎绝手/老奶奶→Snapfire …），跑：
     ```bash
     python3 scripts/list_matches.py --hero <英文名>
     ```
     脚本按时间倒序列出该英雄的对局并标"**第N近**"。
   - **没点名英雄**（如『最近一场』『倒数第三把』）→ 不带 `--hero` 跑 `python3 scripts/list_matches.py`，列最近全部对局。
   - 按用户的**序数**取：**"最近的/上一把/上一局"=第1近，"倒数第二近的/上上把"=第2近，"倒数第三"=第3近**，依此类推。
   - **解析完先用一句话告诉用户你定位到哪局**（例如"解析为 match 8858979802（幽鬼，06-20，胜）"），再进第 1 步——这样用户能一眼发现有没有解析错。
   - 若该英雄近期没有对局、或序数超出范围 → 把候选列表给用户看请其确认，**别硬猜**。

### 1. 跑脚本取数（确定性，别手算）

```bash
python3 scripts/fetch_match.py <match_id> --out /Users/aaron/code/aiagent-study-self/resources/dota2/复盘/_review_<match_id>.md
```

- 脚本会**自动触发解析并轮询**到完成（通常 30 秒–3 分钟）。耗时较长，**建议后台运行**（`run_in_background`）或耐心等待；轮询内部用 python `time.sleep`，不要在 bash 里写 `sleep`。
- 脚本输出一张 **markdown「数据卡」**，含：个人总览、百分位、全员表、**3e BP/选人顺序**、**3b 首个大件**、**3c 首件/中件时间轴+power spike**、**3d 经济来源+farm 分布**、对线@5@10、击杀/死亡时间线、**5b 团战参与**、**5c 视野做眼**、**5d 死亡代价+买活**、**5e 伤害去向**、团队优势曲线+转折点、**6b 四阶段**、**6c 胜率曲线/throw 度**、**6d 关键决策点**、出装顺序、MVP-proxy、8b 队友因素、第 9 节 **信号 JSON**（新增 `draft/item_impact/economy/teamfights/vision/death_cost/damage_focus/phases/throw/decision_points` 等块，**别原样塞给用户**）。
- **BP（3e）不需解析**，其余深挖节需解析。**若"本局未能解析"**：只有 KDA/净值/GPM + 3e BP，**对线@10、逐分钟曲线、3c/3d/5b/5c/5d/5e/6b/6c/6d 均不可用**。如实说"录像已过期，只能基础复盘"，算不了的标"数据缺失"，别编。

### 1b. （可选，推荐）跑 STRATZ 增强取数 → 追加"第 10 节 STRATZ 评价"

```bash
python3 scripts/fetch_stratz.py <match_id> --append /Users/aaron/code/aiagent-study-self/resources/dota2/复盘/_review_<match_id>.md
```

- 只取 OpenDota **没有**的增量：**IMP**（每局每人表现分，正=拉高赢面/负=拖累，按英雄/分路/位置/段位/时长归一）、**对线胜负判定**(win/lose/draw/stomp)、**奖章**、**位置识别**。会把"## 10. STRATZ 评价"+ 一段 `stratz` 信号 JSON 追加到上面那张数据卡末尾。
- **无 token / 该局 STRATZ 未解析 / 403 / 网络失败 → 脚本自动静默降级**（只写一行说明、不报错、不编数）。这一步**失败不影响**用 OpenDota 九节正常出复盘。
- **OpenDota 录像过期但 STRATZ 仍有数据时**：第 1 步九节会标"数据缺失"，但这一步往往**还能给出 IMP / 对线判定 / 奖章**——老局复盘要善用这点。
- 这步也用 OpenDota 之外的网络，沙箱拦网时同样加 `dangerouslyDisableSandbox`；很快（单次 GraphQL 请求），无需后台。

### 1c. （可选，推荐）跑英雄相性取数 → 追加"第 11 节 英雄相性"

```bash
python3 scripts/fetch_matchups.py <match_id> --append /Users/aaron/code/aiagent-study-self/resources/dota2/复盘/_review_<match_id>.md
```

- 针对**你这局所用英雄**，拉它与在场其它英雄的**历史胜负相性**（大样本先验，非本局数据）：
  - **11a 队友协同**（`with`）：你的英雄和每个队友英雄**同队时的历史胜率 + synergy**——高=天生好配合。
  - **11b 对手克制**（`vs`）：你的英雄 **vs 每个对手英雄的历史胜率 + synergy**——>52% 你克他 / <48% 他克你。
- 数据源：**STRATZ 优先**（同时给协同+克制），无 token / 失败 → **回退 OpenDota**（只能给对手克制、无协同）。追加"## 11. 英雄相性" + `matchups` 信号 JSON。
- **不需要解析录像**（直接读阵容 hero_id），所以**老局也能用**，很快，无需后台。失败静默降级。
- 用法：这是**选人层面的先天相性**——被克多/协同差 = 这局阵容你先天吃亏（是"非战之罪/选人问题"的一个佐证）；反过来你**天生占优却输了**，就更该往自己发挥或节奏找问题。**注意**：它是英雄层面的统计先验，不是本局因果，必须和 3c/6b 的本局实际数据交叉着讲，别拿它单独定论。

### 1d. （可选，推荐）跑跨局趋势 → 追加"第 12 节 近况趋势"

```bash
python3 scripts/fetch_trend.py --append /Users/aaron/code/aiagent-study-self/resources/dota2/复盘/_review_<match_id>.md
```

- **不带 match_id**（看的是账号近况，不是某一局）：拉最近 N 局（默认 20，`--last` 可调），算**近 N 局胜率、当前连胜/连败、最长连败、专坑英雄(≥3局胜率≤34%)/本命英雄(≥3局胜率≥60%)、上头(tilt)检测**。
- **纯 OpenDota、无需 token、无需解析，很快**。追加"## 12. 跨局趋势" + `trend` 信号 JSON。失败静默降级。
- 用法：**把"这局"放进"最近这一串"看**——若本局判为非战之罪、但 `trend` 显示你**连败 + 反复拿专坑英雄 + 当天狂打**，那真正的改进是**近况层面**（下号止损、换回本命/强势位），比只盯单局有用。**与 dota2-playtime 台账互补**：那个管"玩太久了"（时长健康），这个管"越打越崩"（战绩趋势）。
- **触发了 tilt 信号时**：报告的"下一步"要明确写"这把之外，近况已在连败/上头，建议收手或换英雄"，别只就单局论单局。

### 2. 读数据卡 + 信号 JSON，写复盘报告

把脚本输出（尤其信号 JSON）作为**唯一事实来源**，结合下方【玩家画像】写报告。**所有数字必须来自数据卡，不要自己估。** 报告固定五节（对应用户的五个诉求）。

> **若数据卡里有"第 10 节 STRATZ 评价"（含 IMP/对线判定/奖章）**：把它当**更可信的主口径**——IMP 是 STRATZ 神经网络按英雄/分路/位置/段位/时长归一后的"表现分"，比自研 MVP-proxy（仅本局 10 人内拍权重的 z 分）更准。**有 IMP 时：第四节责任判定优先看 IMP 及其队内排名、第五节"为什么没拿 MVP"优先用 STRATZ 奖章 + IMP 差、第一节对线用 STRATZ 判定交叉验证 @10。** MVP-proxy 退为对照（两者一致就增强信心，不一致就在文里点出来）。没有第 10 节就照旧只用 OpenDota 九节。

#### 报告模板（务必覆盖这些节；标 ★ 为本次新增维度）

```
# 单局复盘 · match <id> · <英雄>（<位置>）· <胜/负> · <时长>

## 〇、一句话结论
（先给最重要的判断：**这局主要赢因/输因是什么**——你的发挥 / 队友·阵容差距 / 对面滚雪球 / 节奏没收住；并一句话定性你个人是 没问题 / 选人 / 打法。全部基于数据。）

## 一、对线复盘（@5 / @10 + 对线期补刀）
（用数据卡第4节：你 vs 对位的 @5@10 正补/金钱/经验差 → 判定对线优/劣/平。
 注意区分"补刀账面"和"对线期死亡/丢塔"——补刀赢了但送好几次/丢塔，也是对线没真赢。
 **有第10节时**：拿 STRATZ 的对线判定(win/lose/draw/**stomp**) 交叉验证。）

## 二、★ 四阶段 + throw 度 + 关键决策点
（把"局势怎么走的"讲透，三块数据合起来：
 - **四阶段**（6b `phases`）：逐段"金钱差 Δ + 谁赢了这段 + 为什么变（团战净金/拆塔丢塔/肉山/你个人 K-D-补刀）"。例如"对线五五→游走期丢 3 塔+团负转劣→后期被一波带走"。
 - **throw 度**（6c `throw`）：峰值/谷值/终局赢面。`kind=throw`=优势局崩盘（你方一度赢面很高却输，重点查"优势怎么没的"，常对应玩家画像"赢了不会收"）；`kind=comeback`=劣势翻盘；`normal`=胜负与优势一致。
 - **关键决策点**（6d `decision_points`）：肉山/盾、兵营、大团战逐点标了"之后 3min 金钱差 + 当时赢面"——用它定位**是哪个决策（打盾/上高/接团）把局势带走的**。
 这是旧"局势转折点"的升级：不只说"哪一刻崩"，而是四段趋势 + 崩没崩盘的量化 + 具体是哪个决策点。）

## 三、★ 团战 / 击杀被杀 / 视野 / 死亡代价 / 伤害去向
（把"你在团战期的个人表现"一次讲透，用多块数据交叉：
 - **团战参与**（5b `teamfights`）：参与率、团战净金钱、团战内死亡、团胜场。参与率低=游离；参与了但净金为负/反复死=站位或进场时机差。
 - **死亡时间线/分布**（第5节）+ **死亡代价**（5d `death_cost`）：躺尸时间及占比、是否远超队均、买活次数时机。死在对线期=对线送；后期团战死多=定位问题；躺尸占比高=farm/参团双输。
 - **伤害去向**（5e `damage_focus`）：你的伤害是不是砸在了该秒的对面核心上；`fed_core_dmg_share` 低=目标选择有问题（乱 A 肉盾/辅助）。
 - **视野做眼**（5c `vision`）：核心做眼少是常态，但"一个眼不插"或全队视野被碾压要点出；辅助视野拉胯是**队友问题**（前面复盘里就用它证过"VS/白虎其实在做眼"）。）

## 四、★ 出装 / 大件影响 / 经济来源
（用数据卡 **3c**(`item_impact`) + **3d**(`economy`) + 第7节出装顺序：
 - **核心成型竞赛**(`core_first_item_race`)：你方 vs 敌方谁的核心先出首个大件——早成型=先滚雪球，常是节奏分水岭。
 - **你自己的出装**：首件/中件选得对不对（打架件 vs farm 件）、关键保命件(BKB)时机（对照玩家画像"BKB 常年偏晚"病根）。
 - **敌方核心 power spike**：对面靠哪件滚起来，你方有没有在他成型前打断。
 - **经济来源**(3d)：`fight_ratio` 打架钱占比、farm 分布（线上/野区/远古）。吃 farm 核打架占比过高=被迫打架没发育（结合 3b 队友出装看是不是被逼）；辅助 farm 收入过高=在抢核心钱（用它验证"队友抢钱"这类指控——net worth 低要先看是不是买活/farm 少，别只看净值）。
 - `notable_core_swings_correlational` 是**相关非因果**，只能佐证，必须结合 5b/6b 一起说。）

## 五、★ 选人：BP 顺序 + 英雄相性
（把"选人先天顺不顺"讲清，两块合看：
 - **BP 对抗**（3e `draft`）：你的英雄第几手选出、在你之后 pick 的对手是谁（可能是冲你来的 counter）。早手=盲选易被克，晚手=你有反选信息优势。
 - **英雄相性**（11 `matchups`）：11b 你被几个对手克(<48%)/克几个(>52%)、11a 和队友的协同胜率。
 **合起来的杀手锏**：把"在你之后 pick 的对手"和相性一对——如果对面在你选人后专门 pick 了克你的英雄，那就是"draft 阶段被针对"，是最硬的选人吃亏证据。
 结论：被克多+协同差+被 counter-pick=选人先天吃亏（非战之罪一侧）；先天占优/晚手还输=更要往自己发挥找。**务必标注相性是统计先验、非本局因果**，和一/二/四实际数据一起讲。无 STRATZ 时只有对手克制、无协同。）

## 六、责任点（从你个人角度）——这是重点
```

## 责任判定规则（第四节怎么判）

用信号 JSON 里的客观量 + 玩家画像，按下面的证据链判，**给出明确结论而不是和稀泥**：

**总原则**：先用数据定**主因**（你的发挥 / 队友·阵容差距 / 对面滚雪球 / 节奏没收住），再展开；对你个人表现的所有判断**必须基于数据**（百分位、队内排名、对线差、死亡分布），不要凭印象给你安一个数据不支持的问题。

- **STRATZ IMP（有第10节 `stratz` 信号时，这是判"你个人到底拉没拉"的首选口径）**：`my_imp`（正=拉高团队赢面/负=拖累）、`my_imp_rank_in_team`、`my_imp_rank_overall`、`award.mine`。判读：IMP≥+10 且队内第1–2 → 你打得好，输了基本是队友/阵容锅(再看 8b 坐实)；IMP≤−15 且队内垫底 → **你确实是问题的重要一环，别甩锅**；中间值结合 benchmarks/8b 综合。IMP 与 MVP-proxy 结论一致 → 互相印证；不一致 → 以 IMP 为主、并说明分歧。`lane_outcomes`/`my_lane_outcome` 用于交叉验证对线。
- **对线**：`lane.verdict` + 对线期死亡数(`deaths.lane_deaths`)。补刀赢但送≥2 或丢塔 → "对线账面赢、实则因送死没建立优势"。**有 STRATZ 时**再叠加 `my_lane_outcome`(win/lose/draw/**stomp**)：被判 stomp=对线被碾压(严重)，与 @10 互证。
- **个人发挥**：`benchmarks` 多数 <p35 → 你这局发挥确实差；多数 >p55 → 你打得不错。结合英雄定位看关键项（核心看 GPM/净值/英雄伤害，辅助看参团/视野/治疗）。**有 STRATZ 时 IMP 优先**（它已按英雄/位置归一，比生 benchmarks 更公平地评辅助/法核）。
- **送死**：`deaths.total` 明显高于 `deaths.team_avg`、或脆皮英雄死亡两位数 → 站位/决策问题（个人可控）。
- **队友因素（数据化，务必量化——别只凭感觉甩锅或背锅）**：用数据卡第 8b 节 / `context` 里的：`my_rank_in_team_by_impact`（你在本队影响力第几）、`team_flops_excl_me` vs `enemy_flops`（双方"崩盘玩家"=击杀+助攻<死亡 的人数与英雄）、`team_top_core` vs `enemy_top_core`（双方最肥核心净值）、`team_total_nw` vs `enemy_total_nw`（全队总经济）。
  - **你队内影响力第 1–2、却输了**，且 **你方崩盘人数 > 敌方** 或 **你方最肥核心/总经济被敌方明显碾压** → **主因是队友/阵容差距，不是你**。明说"队友差距过大，这种局基本赢不了（非战之罪）"，**别为了'找问题'硬给你安一个数据不支持的个人问题**；最多附一句"硬要说能做得更好的小点"。
  - **你队内垫底（第 4–5）/ benchmarks 多项 <p35** → 你也是问题的一部分，如实承认，不能拿队友当挡箭牌。
  - **中间情况**（你中游、双方崩盘人数相当）→ 你和队友各担一部分，分别讲清。
- **队友出装 / 阵容上下文（务必看数据卡第 3b 节"双方首个大件"——这是 IMP/benchmarks 的盲区）**：定责前先看队友（尤其你方核心）的首个大件取向，以及两队阵容性质。典型陷阱：
  - **你方核心裸贪 farm 大件（双辉耀/漩涡/狂战/midas）打进对面打架阵容**（斧王/小娜迦/火猫/Slark/食人魔这类）→ 前中期你方没有战斗力，**你被迫成为唯一打架/守塔的人**。这会让你**farm 低、人头高、助攻低**——这是**被队友出装/阵容逼出来的，不是你不会 farm、不是你不参团**，别算你头上。这种局即便你 IMP 垫底也常是**非战之罪**。
  - **关键认知：IMP（及 benchmarks/MVP-proxy）看不到"队友裸双辉耀逼你弃 farm"这种上下文**——它只看到"核心 farm 低 + 输了"就给你扣到最低。**当数据卡第 3b 节明显显示队友出装拖累/阵容被克时，以这个上下文为准、可以推翻一个偏低的 IMP**，并在报告里说清"IMP 在本局是盲区误判"。反过来，3b 显示你方出装阵容正常、你却 farm 低 IMP 低，那才是你的问题。
- **选人**：结合玩家画像判这英雄**适不适配他**（不是版本强度）——他打**冲脸/先手/耐久**强、**脆皮执行法核/站后排/吃farm核**弱。若他选了不适配自己的英雄且这正是输点之一 → 点出"选人与你的强项不符"。**注意结合 3b：若你方核心出装/阵容已经决定了打法（如逼你打架），别再拿"你没按本英雄标准打法"苛责。**
- **★ 英雄相性（`matchups` 信号）**：`vs` 里你被克(<48%)的对手数 / 你克(>52%)的对手数、`with` 里协同差的队友。**被克多+协同差=选人先天吃亏**，是"非战之罪/选人问题"的一个客观佐证（区别于玩家画像的"适配"，这是英雄客观相性）。但**先天占优却输**→别拿相性当挡箭牌，往自己发挥/节奏找。相性是统计先验、非本局因果，只作佐证，结论仍以本局实打实数据为主。
- **★ 四阶段（`phases` 信号）**：逐段 `verdict`+`reasons` 定位"是哪一段、因什么把优势/劣势拉开"。典型：对线赢但**游走期**因你死多/丢塔转劣（你的锅）；或对线/中期都赢、**后期**被对面大核一波带走（转化问题或核心 carry 差距）。把责任落到**具体阶段的具体事件**上，比笼统"崩了"有用。
- **★ 团战参与（`teamfights` 信号）**：`participation_rate` 低（<60%）=该打的团没到（游离，个人可控）；参与率高但 `my_net_gold` 为负 / `my_deaths_in_fights` 高=进场时机/定位差；`team_won_fights` 少但你团战数据好=队友团战拉胯。
- **★ 出装影响（`item_impact` 信号）**：`core_first_item_race` 敌方核心明显先成型=对面先获得 power spike、滚雪球先手（偏节奏/非战之罪一侧）；你自己**保命件(BKB)偏晚**（对照玩家画像病根）=可控打法问题。`notable_core_swings_correlational` **仅相关非因果**，只能和 6b 团战/推塔一起佐证，禁止单独用它下"某件决定胜负"的因果结论。
- **★ 经济来源（`economy` 信号）**：`fight_ratio` 过高 + farm 收入低 = 被迫打架没发育（吃 farm 核，结合 3b 看是否被队友逼）。**验证"队友抢我钱"这类指控专用**：看被指控者的 farm 收入/farm 分布，而不是只看净值——净值低可能是买活(`death_cost.buyback_count`)或本就 farm 少；`gold_lost_on_death` 是你自己死亡掉的钱。
- **★ 视野（`vision` 信号）**：`my_ward_rank_in_team`、你方 vs 敌方 obs/sen 总数。核心做眼少正常、别苛责你；但**辅助视野被敌方碾压=队友问题**（可为你脱责的一个佐证）；你若"一个眼不插"且是劣势的一环，如实点出。
- **★ 死亡代价（`death_cost` 信号）**：`dead_pct` 躺尸占比远超 `team_avg_dead` = 你死得太频繁/死在关键期（个人可控，farm 参团双输）；买活时机(`buyback_times`)不当=经济决策问题。
- **★ 伤害去向（`damage_focus` 信号）**：`fed_core_dmg_share` 低 = 团战没集火对面大核、伤害浪费在肉盾/辅助上（可控的目标选择问题）；高 = 你打对了目标但仍输 → 往队友/节奏找。
- **★ BP（`draft` 信号）**：`enemy_picked_after_me` 里若有第 11 节判为克你(<48%)的英雄=**draft 阶段被针对**（选人吃亏、偏非战之罪）；你是晚手(`my_pick_index` 大)却还选了被克的英雄=选人可检讨。
- **★ throw 度（`throw` 信号）**：`kind=throw`（输了但峰值赢面≥70%）=**优势局崩盘**，这是可控的重大问题，直接对应玩家画像"赢了不会收/决胜窗口崩盘"，责任要落到你/团队没收住优势；`kind=comeback`=你方翻盘赢（赢因写清）；`normal`=胜负与实力一致，别硬套 throw。
- **★ 决策点（`decision_points` 信号）**：找 `gold_swing_next3` 大幅转负那个事件=**把局势带走的决策**（如"打了个亏盾/强上高被团灭"）。若崩盘点是某个具体决策 → 比笼统"后期崩了"精确得多，直接指出来。
- **★ 跨局趋势（`trend` 信号，第12节）**：`tilt_signals` 非空（连败/当天狂打/反复专坑英雄）→ **即使单局非战之罪，也要在"下一步"点出近况问题**（下号止损/换英雄）。`trap_heroes` 含本局英雄=你在一个近段专坑的英雄上又输了，选人建议要落到"换回 `core_heroes`/强势位"。这是"单局甩不甩锅"之外的、更重要的近况层面判断。

结论三选一并允许组合：**①选人问题(含英雄相性先天吃亏) ②打法问题(注明对线/送死/出装时机/团战进场/优势转化哪一类) ③基本没问题（锅在某队友或全队，注明是谁）**。

> **核心原则：队友差距太大也是赢不了的。** 当数据显示你发挥在均线之上、队内靠前，而对方阵容/核心碾压你方时，结论就该是"非战之罪"——诚实地讲清"主要赢因/输因"，比"每局都硬揪出你一个错"有用得多。反过来，数据显示你确实拉了（队内垫底/benchmarks 差），也要直说，别甩锅队友。**一切以数据为准。** 个人分析可以**更细**（分阶段死亡、对线差、各项百分位、与队内对比），但都要落在数据上。

## 数据化 Dota2 的维度路线图（"还能分析什么"）

目标：把"凭感觉复盘"彻底换成"数据驱动"。下面是全量维度清单——**✅=本 skill 已实现、🔜=数据现成好加、💡=需额外取数/建模**。用户想扩哪块，按此加脚本即可（OpenDota 单局 JSON 已含绝大多数原始字段：`purchase_log/teamfights/obs_log/sen_log/runes_log/damage_targets/actions/neutral_kills/lane_kills/buyback_log/kill_streaks/lane_pos/times/lh_t/gold_t/xp_t`）。

**已实现**
- ✅ **英雄相性**：你这局英雄 × 队友协同(with) + 对手克制(vs) 历史胜率/synergy（STRATZ/OpenDota）。→ 第 11 节 · `matchups`
- ✅ **出装影响**：全员首件/中件时间轴、核心成型竞赛（谁先 power spike）、核心大件±5min 团队金钱差（相关佐证）。→ 第 3c 节 · `item_impact`
- ✅ **经济来源 + farm 分布**：打架钱 vs farm 钱占比、补兵/打野/推塔/肉山/死亡损失拆解、线上/野区/远古 farm 分布。→ 第 3d 节 · `economy`
- ✅ **团战参与度**：参与率、团战净金钱、团战内死亡、团胜场。→ 第 5b 节 · `teamfights`
- ✅ **视野做眼**：你/全队 假眼真眼数、队内做眼排名、双方视野对比。→ 第 5c 节 · `vision`
- ✅ **死亡代价 + 买活**：躺尸时间及占比/队均对比、死亡掉金、买活次数时机。→ 第 5d 节 · `death_cost`
- ✅ **伤害去向**：你的英雄伤害砸在每个对手头上的占比、对面最肥核心吃到你多少伤害（目标选择对不对）。→ 第 5e 节 · `damage_focus`
- ✅ **四阶段优劣势**：对线/游走gank/刷钱/后期逐段金钱经验 Δ + 变化原因（团战净金/拆丢塔/肉山/个人 K-D-补刀）。→ 第 6b 节 · `phases`
- ✅ **BP/选人对抗**：pick 顺序、你第几手、在你之后被 pick 的对手（可能针对你）、ban。→ 第 3e 节 · `draft`
- ✅ **throw 度/胜率曲线**：启发式赢面模型，量化"优势局崩盘(throw)/劣势翻盘(comeback)"，报峰值/谷值/终局赢面。→ 第 6c 节 · `throw`
- ✅ **关键决策点自动标注**：肉山/盾·兵营·大团战 → 逐点标时间+之后 3min 金钱差+当时赢面。→ 第 6d 节 · `decision_points`
- ✅ **跨局趋势（近况）**：近 N 局胜率、连胜连败、最长连败、专坑/本命英雄、上头(tilt)检测。→ 第 12 节 · `trend`（独立脚本 `fetch_trend.py`）
