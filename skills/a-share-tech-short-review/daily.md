# daily 子命令 · 关注列表每日批量复盘

`a-share-tech-short-review` 的批量模式：读取**关注列表文件**里的全部股票，逐只跑一遍本 skill 的完整复盘流程，把每只票的结论压缩成 **500~1000 字**，汇总成**一份按「日期-序号」命名的 md**（一天可跑多次，每次新开一份，不覆盖）。

> 与主流程的关系：`daily` **不是新方法论**，只是「读列表 → 对每只票执行 SKILL.md 的 §1~§7 → 收敛成一节 → 拼成一份日报」的编排层。归因、多派会诊、必须明确表态等所有硬约束，`daily` 里**一条都不放宽**。

---

## 调用方式

```
/a-share-tech-short-review daily
```

等价形式：

- `用 a-share-tech-short-review 跑 daily`
- `调用 a-share-tech-short-review daily，只跑前 3 只`

同样受主 SKILL.md 的**显式调用**硬约束：用户没点名 skill、只是说「今天大盘怎么样」「帮我看看关注的票」，**不触发** `daily`。

### 可选参数

| 参数 | 说明 | 默认 |
|---|---|---|
| 时间区间 | 每只票的复盘窗口 | 近 **5** 个交易日（同主流程） |
| 关注列表路径 | 输入文件 | `/Users/aaron/workspace/个人/投资分析记录/关注的A股股票.md` |
| 输出目录 | 日报存放位置，**按年份分目录** | `/Users/aaron/workspace/个人/投资分析记录/<YYYY>record/`（如 2026 年 → `2026record/`） |
| 只跑子集 | 如「只跑光模块那几只」「只跑前 3 只」 | 全部 |
| `--keep-single`（口头说「每只也单独出报告」即可） | 额外把每只票的完整长报告写到 `/Users/aaron/workspace/llmWikis/investWiki/others/research/`（文件名同主流程） | **关闭**，`daily` 默认只产出汇总日报 |

## 执行步骤

### 0. 每次都重新读关注列表（硬要求）

```
Read /Users/aaron/workspace/个人/投资分析记录/关注的A股股票.md
```

- **禁止**使用上一次运行缓存的名单、也禁止凭记忆列票。该文件会被用户随时增删改，**每次 `daily` 必须现场重读**。
- 解析规则：取 `- ` 开头的列表项作为标的；忽略标题行（`#`/`##`）、空行、注释行（`>`、`<!-- -->`）。
- 条目可能是**名称**（如「中际旭创」）、**代码**（如「300308」），或「名称 代码」混写；三种都要能吃下。
- 名称可能是**简写/俗称**（如「长飞光纤光缆」实为「长飞光纤」601869）——用 `WebSearch` 核对成 6 位代码，**别张冠李戴**。
- **不要停下来等用户确认**：解析完把「名称 → 代码」映射打到终端**知会一声就直接开跑**，`daily` 是无人值守的批量命令，不设确认关卡。映射若有错，用户看到输出自会打断。
- 唯一的例外是**真解析不出来**：某条目搜出多个同名标的、或压根查不到对应 A股代码时，**别猜**——把该条目记为失败跳过、继续跑其余标的，在日报开头的「本次未完成」里写清原因，让用户事后改 `关注的A股股票.md`。
- 列表为空 / 文件不存在 → 直接告知用户并停止，不要自己编一份名单。

### 1. 逐只执行主流程

对名单里**每一只**票，按 `SKILL.md` 的执行步骤跑：

1. §1 解析输入（代码、窗口、是否科技股）
2. §2 `scripts/fetch_ashare.py` 拉行情识别异动
3. §3 产业链上下游/同业联动对比
4. §4 逐个异动联网查因（多维度 + 诚实归因）
5. §5 平静期简报（无异动也不空手）
6. §6 forSkills 多派镜头会诊
7. §7 收敛成明确投资建议（方向＋力度＋操作要点＋改判条件＋置信度）

**批量模式下的执行注记：**

- **开跑前先取真实时刻**（不许凭 `currentDate` 推、不许估）：

  ```bash
  date "+%Y-%m-%d %H:%M %Z"
  ```

  记为**分析开始时刻**；每只票跑完各记一次该票的**分析时刻**；全部跑完再取一次作为**分析结束时刻**。三者都精确到**分钟**，写进日报（见 §3）。
- **默认串行**，一只跑完再跑下一只。10 只票 × 完整联网复盘耗时不短，开跑前先告知用户预计要跑几只。
- **产业链对比可复用**：名单内部常常同属一条链（如光模块/光器件扎堆），同窗口已拉过的个股行情**直接复用**，不要对同一代码重复调脚本。
- **共享的板块/海外映射**（SOX、NVDA 隔夜、半导体 ETF、当日大盘）在整轮开始时查一次，各票共用，避免十次重复搜索。
- **单只失败不中断**：某只票取数失败或代码解析不了，记下失败原因，该节写「本次未取到数据：<原因>」，继续下一只。全部跑完后在日报开头汇总失败清单。

### 2. 把每只票收敛成 500~1000 字

每只票在日报里占**一个二级小节**，正文 **500~1000 字**（不含表头/链接列表）。这是压缩，不是删减——下列要素**必须全在**：

- 近窗涨跌幅与是否触发异动阈值（单日 ≥±5% / 累计 ≥±10%）
- 主驱动归因分层：个股 alpha / 产业链传导 / 板块情绪 / 大盘系统性，能量化超额就量化
- 关键异动日的催化及证据（带链接与日期），**查无催化就直说「未找到明确催化（疑资金/情绪/技术性）」**
- 产业链与海外映射里跟本票直接相关的那一两条
- 多派会诊的**结论**（哪派主导、哪派让位），不用铺开整张矩阵
- **明确的投资建议**：方向（买/加/持/减/清/观望）＋力度＋操作要点＋改判条件＋置信度
- **该票的分析时刻**（精确到分钟）：批量跑一轮可能横跨一两个小时，第 1 只和第 10 只面对的盘口完全不同，建议必须能追溯到「几点几分做出的」

字数不够多半是漏了归因层或改判条件；超过 1000 字就把逐日流水账压成结论。

### 3. 写日报

- 输出目录：**按年份分目录** `/Users/aaron/workspace/个人/投资分析记录/<YYYY>record/`，年份取 system `currentDate` 的年（2026 年 → `/Users/aaron/workspace/个人/投资分析记录/2026record/`）。
  - 年份目录**不存在就先建**（跨年第一次运行会遇到）：

    ```bash
    mkdir -p /Users/aaron/workspace/个人/投资分析记录/<YYYY>record
    ```

  - **禁止**再往上一级的 `投资分析记录/` 根目录里写日报；那里只放 `关注的A股股票.md` 等输入文件和历史遗留文件。
- 文件名：**`<YYYY-MM-DD>-<序号>.md`**（日期按 system 的 `currentDate` 取），如 `2026record/2026-08-17-1.md`、`2026record/2026-08-17-2.md`。
- **一天可能跑多次，每次都写新文件，永不覆盖**。序号取法：先列**当年目录**

  ```bash
  ls /Users/aaron/workspace/个人/投资分析记录/<YYYY>record/<YYYY-MM-DD>-*.md 2>/dev/null
  ```

  取已存在的最大序号 +1；一个都没有则从 **1** 起。序号不补零（`-1` 而非 `-01`），逐次递增不跳号、不复用。序号**只在当年目录内**统计，不跨年沿用。
- **必须写明分析时间，精确到分钟**（硬要求，不是可选元信息）：
  - 日报开头元信息行写 `分析时间：<YYYY-MM-DD HH:MM> ~ <HH:MM>（<时区>）`，即整轮的开始与结束时刻。
  - 每只票小节的**建议行**末尾带该票的分析时刻 `｜ 分析时刻 <HH:MM>`。
  - 时间一律取 `date` 的真实输出，**禁止写「上午」「盘中」「约 10 点」这类模糊表述，禁止事后估算或补编**。
  - 盘中跑的日报还要在元信息里标注**行情数据截止时刻**（脚本取到的最后一根 K 线是哪天收盘 / 是否为盘中快照），避免事后误以为是收盘结论。
- 因为不覆盖，**无需任何确认**：直接写新序号文件，跑完把完整路径告诉用户即可。
- 同一天的多份日报各自独立完整（不要写成「同上一轮」的增量），但可在开头一行注明「本日第 N 次运行，上一份：`<YYYY-MM-DD>-<N-1>.md`」，方便对照当天盘中变化。
- 小节顺序 = 关注列表里的顺序，便于用户按自己的排布对照。

## 注意事项

- **时间戳必须真实**：分析时间来自 `date` 实测，精确到分钟，起止与每票时刻缺一不可。这是短期复盘的核心元数据——同一只票 10:15 和 14:40 的建议可能相反，没有时刻的建议事后无法复盘对错。
- **日报一律落在当年目录**：`<YYYY>record/` 是唯一合法输出位置，年份跟着 `currentDate` 走；跨年后自动切到新目录（先 `mkdir -p`），旧年份日报留在原目录不迁移。
- **名单永远以文件为准**：`关注的A股股票.md` 是唯一事实源，用户改了文件下次跑就自然生效；skill 侧不留任何硬编码名单。
- **不许为了赶进度跳过联网查因**：宁可告诉用户「名单太长，本轮先跑前 N 只」，也不要给一节没有证据、靠推测编出来的归因。
- **诚实归因照旧**：批量不是编造的借口，查不到催化就写查不到，每条结论带置信度。
- **必须逐只表态**：每一节都要落到明确建议，不许出现「建议观察，仅供参考」式的整节回避（「观望」是合法表态，但要给出观望的条件与改判触发点）。
- **非科技股/非 A股**：若名单里混入了非科技股或港美股，按主 SKILL.md「适用范围」提示用户，仍可跑但标注产业链/海外映射维度弱化。
